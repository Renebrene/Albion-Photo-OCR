## 1. ЗАДАЧА  
Решалась задача улучшения распознавания маленьких табличек с помощью OCR, но текущий подход с разбиением изображения на тайлы не позволял обнаружить табличку. Основной фокус — сохранить OCR как экспериментальный модуль, но не включать его в основной pipeline распознавания адресов.

---

## 2. ФАЙЛЫ И МОДУЛИ  
- `app/ocr/` — модуль OCR, используемый для распознавания текста (не включён в основной pipeline).  
- `v33` — версия fingerprint/слепок, используемая в основном pipeline.  
- `recognize` — команда для запуска распознавания (указана как точка продолжения работы).  

---

## 3. АРХИТЕКТУРА  
- **Технология/фреймворк**:  
  - DINOv2 — для генерации слепков/отпечатков.  
  - OCR — для распознавания текста (экспериментальный модуль).  
- **Паттерны проектирования**:  
  - Разделение на модули (OCR, fingerprint, pipeline).  
  - Отдельный экспериментальный модуль (OCR) для будущего использования.  
- **Структура данных**:  
  - Координаты тайлов (например, `bbox=(2078,1026,2539,1371)`).  
  - Текстовые отпечатки для поиска похожих баннеров.  

---

## 4. НАПИСАННЫЙ КОД  
- Пример вывода координат тайлов:  
  ```text  
  TILE 046  
  bbox=(2078,1026,2539,1371)  
  ```  
- Результаты эксперимента с OCR:  
  ```text  
  OCR CPU — рабочий.  
  Скорость — хорошая.  
  Grid OCR — технически работает.  
  Маленькую табличку данным способом не нашли.  
  ```  
- Схема основного pipeline:  
  ```text  
  Новая фотография  
        ↓  
  DINOv2  
        ↓  
  fingerprint v33  
        ↓  
  TOP кандидатов  
        ↓  
  берём ПЕРВОГО кандидата  
        ↓  
  присваиваем его адресу  
  ```  

---

## 5. НЕЗАВЕРШЁННОЕ  
- [ ] Увеличение количества тайлов для улучшения распознавания табличек (не реализовано).  
- [ ] Интеграция OCR в основной pipeline (отложено).  
- [ ] Дальнейшая оптимизация алгоритма распознавания (не выполнено).  

---

## 6. КЛЮЧЕВЫЕ РЕШЕНИЯ  
- **Остановить эксперимент с OCR** → избежать избыточной сложности и роста времени выполнения.  
- **Оставить OCR в `app/ocr/` как отдельный модуль** → для будущего использования в поиске похожих баннеров.  
- **Продолжить основной pipeline (DINOv2 → fingerprint → адрес)** → сохранить стабильность и производительность.  
- **Использовать `recognize` как точку продолжения** → избежать перестройки текущего состояния.
