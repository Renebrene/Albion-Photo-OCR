**Итоговый план для обработки изображений с таблицей "Разр. № XXXXX":**

---

### 🧠 **Основные принципы**
1. **OCR + SQL + Детектор текста** — три основных компонента.
2. **Не доверять одному OCR** — использовать голосование и коррекцию по БД.
3. **Динамический поиск текста** — не фиксировать область, где находится таблица.
4. **Нормализация и коррекция** — использовать SQL для сопоставления номеров.

---

### 🧩 **Шаги реализации**

#### 1. **Детектор текста по всей фотографии**
- Обрабатываем изображение `3500×2500` без ограничений.
- Разбиваем на перекрывающиеся области (например, 15–25% перекрытия).
- Используем **OpenCV** или **PaddleOCR** для обнаружения текстовых регионов.

#### 2. **OCR для найденных областей**
- Для каждой найденной области:
  - Увеличиваем в 3–4 раза.
  - Применяем **препроцессинг** (контраст, резкость, серый тон).
  - Используем **PaddleOCR** или **Tesseract** для распознавания текста.

#### 3. **Фильтрация и извлечение номера**
- Ищем шаблоны: `Разр. №`, `Разр №`, `Разр. No`, `Разр. N`.
- Извлекаем номера (например, `7478`) и корректируем ошибки (например, `74Z8` → `7478`).
- Используем **регулярные выражения** и **нормализацию** (например, `7478М` → `7478`).

#### 4. **Сопоставление с БД**
- Проверяем, есть ли номер в БД: `SELECT address FROM permits WHERE permit_number = '7478'`.
- Если номер не найден, используем **голосование** по серии изображений (например, 8 из 10 фото с `7478` → уверенность 94%).

#### 5. **Резервный механизм (DINO)**
- Если OCR не определил номер, используем **DINO** для визуальной группировки.
- DINO помогает сопоставить изображения с известными сценами, если OCR не уверен.

### 🧠 **Итог**
- **OCR + SQL** — основной механизм для извлечения номеров.
- **DINO** — резервный для визуальной группировки.
- **Голосование** и **нормализация** — ключевые для повышения точности.
- **Препроцессинг** и **динамический поиск текста** — обязательные шаги для сложных случаев.
