### Откуда берутся фото-адреса и клиенты для отображения

#### 1. **Фото-адреса (адреса в гриде)**
- **Источник:** `data/output/test_sorted_v2/`
- **Структура:**  
  Фотографии хранятся в подпапках с названием вида `X_v33`, где `X` — это числовой идентификатор адреса.  
  Пример:  
  ```
  data/output/test_sorted_v2/
      78_v33/
      79_v33/
      ...
      95_v33/
  ```

- **Как формируется адрес в гриде:**  
  Адрес извлекается из имени папки, удаляя суффикс `_v33`.  
  Пример:  
  - Файл: `data/output/test_sorted_v2/95_v33/Вавилова52_09.jpg`  
  - Адрес в гриде: `95` (из `95_v33`).

- **Текущее поведение:**  
  Грид отображает адрес как `95`, но **не связывает его с конкретным клиентом**. Это приводит к тому, что фильтрация по адресу и клиенту работает независимо.

---

#### 2. **Клиенты (из БД)**
- **Источник:** `PHOTO_RECORD_INDEX` (строится через `build_photo_record_index`)
- **Как работает:**  
  Для каждого файла создается запись в БД (`PhotoRecord`), где хранится клиент (например, `Клиент А`).  
  Пример:  
  - Файл: `data/output/test_sorted_v2/95_v33/Вавилова52_09.jpg`  
  - Запись в БД: `{"path": "...", "client": "Клиент А"}`

- **Как отображается клиент:**  
  При отображении фотографии клиент берется из `PhotoRecord` по полному пути файла.  
  Пример:  
  - При клике на `Вавилова52_09.jpg` — отображается `Клиент А`.

---

### 🔍 Проблема и рекомендации

#### 1. **Разделение источников**
- **Адрес в гриде** берется из имени папки (`X_v33`).
- **Клиент** берется из БД (`PhotoRecord`).
- **Результат:**  
  Адрес и клиент могут не совпадать (например, файл `95_v33/...` может принадлежать клиенту `Клиент Б`).

#### 2. **Рекомендация: объединить в `PhotoRecord`**
Чтобы упростить фильтрацию и отображение, лучше объединить адрес и клиента в единый объект `PhotoRecord`:
```python
PhotoRecord = {
    "path": "data/output/test_sorted_v2/95_v33/Вавилова52_09.jpg",
    "address": "95",  # из имени папки
    "client": "Клиент А",  # из БД
    "capture_date": "2026-08-17",  # из EXIF
    "collection": "Дневная подборка",  # из метаданных
    "qwen_description": "Описание с помощью Qwen",  # из модели
}
```

- **Плюсы:**  
  - Фильтрация по `address + client + date + collection` станет точнее.  
  - Грид будет использовать `address` из `PhotoRecord`, а не из имени папки.  
  - Упрощается синхронизация между адресом, клиентом и метаданными.

### 📷 Отображение изображений

- **Текущее поведение:**  
  Грид показывает **оригинальный файл** из `test_sorted_v2`, а не превью.  
  Пример:  
  - При клике на `Вавилова52_09.jpg` — открывается оригинальный файл.  
  - Превью (`data/preview/daily/...`) не используется.

- **Рекомендация:**  
  Измените логику, чтобы грид отображал **превью** (`data/preview/daily/...`), а при клике открывал **оригинал**.  
  Это улучшит производительность и уменьшит нагрузку на браузер.

### ✅ Итог
- Адреса в гриде берутся из имени папки (`X_v33`).  
- Клиенты берутся из БД (`PhotoRecord`).  
- Для фильтрации и отображения рекомендуется объединить адрес и клиента в `PhotoRecord`.  
- Грид должен отображать превью, а при клике — оригинал.
