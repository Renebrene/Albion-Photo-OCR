### 🧠 **Решение: Универсальный ID и интеграция с гридом**

Для реализации **универсального ID**, который будет использоваться как для DINO, так и для Qwen, и отображаться в гриде, нужно:

---

### 🔧 **1. Универсальный ID:**
- **`file_hash`** (хэш исходного файла) — уникальный идентификатор, не зависящий от пути.
- **`assigned_id`** (окончательный ID от Hybrid) — используется для отображения в гриде.
- **`dino_id`** — ID, назначенное DINO (может отличаться от `assigned_id`).
- **`qwen_id`** — ID, назначенное Qwen (может отличаться от `assigned_id`).

---

### 📁 **2. Структура индекса (JSON/DB):**

```json
{
  "file_hash": "abc123",
  "source_path": "/input/photo_003.jpg",
  "dino_status": "DONE",
  "dino_id": "78",
  "dino_version": "v33",
  "dino_result": {"score": 0.95, "best_id": "78"},
  "qwen_status": "WAITING",
  "qwen_version": "qwen3-vl-4b",
  "qwen_result": null,
  "assigned_id": "78",
  "grid_position": "row_78_col_1",
  "updated_at": "2026-08-18T23:15:00Z"
}
```

---

### 🔄 **3. Логика работы:**

#### **DINO → Hybrid → Qwen**
1. **DINO** распознаёт фото и назначает `dino_id` (например, `78`).
2. **Hybrid** использует соседей для определения `assigned_id` (например, `78`).
3. **Qwen** получает фото по `assigned_id` и обрабатывает его, используя `dino_id` для контекста.

---

### 🔄 **4. Параллельность:**
- **DINO** работает независимо.
- **Hybrid** использует соседей (не может обработать фото, если соседи не готовы).
- **Qwen** начинает обработку **после** получения `assigned_id` от Hybrid.

---

### 🔄 **5. Индексация:**
- **`sort_results()`** теперь записывает данные в индекс вместо копирования файлов.
- Пример записи:

```python
def sort_results(rows, output_dir):
    ...
    for item in rows:
        # Запись в индекс
        index_db.update({
            "file_hash": item["file_hash"],
            "source_path": item["file"],
            "dino_id": item["dino_id"],
            "assigned_id": item["assigned_id"],
            "grid_position": f"row_{item['assigned_id']}_col_{item['grid_col']}",
            ...
        })
```

---

### 🔄 **6. Управление состоянием:**
- **`file_hash` + версия алгоритма** (например, `v33`) используется для определения, обработан ли файл.
- **`dino_status`** и **`qwen_status`** отслеживают прогресс.
- **`updated_at`** позволяет отслеживать изменения.

---

### 🔄 **7. Продолжение после прерывания:**
- При запуске проверяется:
  - Если `dino_status == "DONE"`, то `dino_id` сохраняется.
  - Если `qwen_status == "DONE"`, то `qwen_result` сохраняется.
- **`assigned_id`** используется для отображения в гриде, даже если обработка не завершена.

---

### 🔄 **8. Обработка заново:**
- Если выбран режим "Обработать заново":
  - **`dino_status`** сбрасывается до `WAITING`.
  - **`qwen_status`** сбрасывается до `WAITING`.
  - **`dino_result`** и **`qwen_result`** очищаются.
- Если выбран режим "Пропустить", то обработка пропускается.

---

### 🔄 **9. Отображение в гриде:**
- **`assigned_id`** используется как ключ для отображения в гриде.
- **`grid_position`** определяет позицию в визуализации.
- Пример:
  ```
  | Grid Col 1 | Grid Col 2 | Grid Col 3 |
  |------------|------------|------------|
  | photo_78   | photo_83   | photo_95   |
  ```

---

### 🔄 **10. Важные моменты:**
- **`file_hash`** гарантирует уникальность идентификатора.
- **`assigned_id`** от Hybrid используется для отображения в гриде.
- **`dino_id`** и **`qwen_id`** отслеживают отдельные этапы обработки.
- **Версия алгоритма** (например, `v33`, `qwen3-vl-4b`) позволяет обновлять логику без потери данных.

---

### ✅ **Итог:**
- **Универсальный ID** объединяет DINO и Qwen через `file_hash` и `assigned_id`.
- **Индексация** позволяет управлять состоянием, продолжать обработку и отображать результаты в гриде.
- **Параллельность** обеспечивается через отдельные очереди для DINO и Qwen.
- **Гибкость** — возможность обработать заново, пропустить или продолжить после прерывания.

Теперь можно переходить к реализации индекса и модификации `sort_results()` для записи в него вместо физического копирования.
