### ✅ **4. Что можно сделать сейчас**

#### 🔄 **a) Проверить, насколько `best` уже решает спорные случаи**

Запустите **DRY RUN** с текущим `best` и без вмешательства LLM:

```bash
cd ~/projects/scene_fingerprint_mvp_v02

uv run python - <<'PY'

    r = csv.DictReader(f)
    for row in r:
        frame = row["frame"]
        top1 = row["top1"]
        top2 = row["top2"]
        margin = row["margin"]
        best_id = row["best_id"]
        best_score = row["best_score"]
        neighbor = row["neighbor"]

        print(f"{frame} {top1} {top2} {margin} {best_id} {best_score} {neighbor}")
PY
```

#### 🔄 **b) Определить, сколько спорных кадров решает `best`**

- Если `best_id` совпадает с `TOP1` и `best_score` > 0.95 — **не нужно вмешиваться**.
- Если `best_id` отличается от `TOP1` и `best_score` > 0.8 — **LLM не нужен**.
- Если `best_score` < 0.8 — **LLM должен проверить**.

---

### ✅ **5. Что оставить для LLM**

LLM вмешивается **только в следующих случаях**:

1. **Слабый `best_score`** (< 0.8).
2. **Конфликт между `TOP1`, `TOP2`, и `best_id`**.
3. **Одиночный выброс** (например, `TOP1=89` между `92` и `92`).
4. **Сложные переходы** (например, `92 → 95 → 81`).

---

### ✅ **6. Как это улучшит систему**

- **Снижение нагрузки на LLM** — он будет вмешиваться только в сложных случаях.
- **Ускорение обработки** — DINO и `best` решают 90% случаев.
- **Устойчивость к ошибкам** — LLM не будет "сглаживать" последовательность вслепую.
