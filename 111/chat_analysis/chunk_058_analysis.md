### 🚀 **Далее: Запуск `sort_neighbor_v35_benchmark.py`**

После успешного запуска `benchmark_test_v1.py`, давай запустим `sort_neighbor_v35_benchmark.py`:

```bash
uv run python scripts/sort_neighbor_v35_benchmark.py
```

Ожидаемый вывод будет включать:

```text
Total images: 256
Margin < 0.005: 42
Changed by neighbors: 27
```

---

### 📌 **Что ожидать:**

1. **`margin_best.csv`** — не будет создан, так как это отдельная ветка.
2. **`neighbor_decision.csv`** — будет сгенерирован, с колонками:
   - `image`
   - `v33` (исходный)
   - `second` (второй кандидат)
   - `final` (корректированный)
   - `margin`
   - `reason` (причина изменения)
   - `second_neighbors`, `current_neighbors`

3. **`SORTED_DIR`** — будет содержать отсортированные изображения по `final` фингерпринтам.

---

### 🧠 **Анализ результатов:**

После запуска:

1. **Проверь `neighbor_decision.csv`:**
   - Сколько изображений изменились (`final != v33`)?
   - Какие фингерпринты чаще всего "перекидываются" между собой?
   - Есть ли явные паттерны (например, "все изображения с 91_v33 перекидываются на 92_v33")?

2. **Проверь `SORTED_DIR`:**
   - Сколько изображений в каждой папке (например, `91_v33`, `92_v33`)?
   - Есть ли "группы" изображений, которые визуально похожи?

3. **Проверь статистику:**
   - Сколько изображений с `margin < 0.005`?
   - Сколько изображений было изменено соседями?

---

### 🔄 **Далее:**

Если `sort_neighbor_v35_benchmark.py` показывает значительное улучшение (например, уменьшение количества "плохих" `margin`), то:
- **v35 уже достаточно** для текущей задачи.
- Можно остановиться на этом.

Если же:
- Изменений мало, или
- Изменения не логичны (например, "91_v33" перекидывается на "94_v33", но визуально они не похожи),
- Тогда стоит вернуться к `margin_best.csv` и `dry_run_best_sequence.py`.
