## 1. ЗАДАЧА  
Решалась задача возврата старой логики распознавания для визуальной проверки качества слепков без изменений в алгоритме. Цель — отделить проблемы алгоритма от проблем fingerprint конкретных адресов.

---

## 2. ФАЙЛЫ И МОДУЛИ  
- `data/output/` — папка с сортированными изображениями и результатами распознавания  
- `recognizer.py` — модуль с логикой распознавания (старая версия)  
- `fingerprint` — модуль для генерации fingerprint  
- `FAISS` — библиотека для поиска кандидатов  
- `upgrade_patch_tokens.sh` — скрипт для оптимизации процесса  
- `.bak`, `.old`, `.orig` — файлы с резервными копиями старых версий  

---

## 3. АРХИТЕКТУРА  
- **Технология/фреймворк**:  
  - DINOv2 — для генерации эмбеддингов  
  - FAISS — для поиска кандидатов  
  - CUDA — для ускорения вычислений  
- **Паттерны проектирования**:  
  - Модульность (разделение на `embedder`, `fingerprint`, `recognizer`)  
  - Разделение логики принятия решений (старая vs новая)  
- **Структура данных**:  
  - Словари и списки для хранения результатов распознавания  
  - Группировка изображений по адресам (например, `test_classified/78...95`)  

---

## 4. НАПИСАННЫЙ КОД  
Код, реально созданный в фрагменте:  
- Команды для поиска файлов:  
  ```bash
  find data/output -maxdepth 3 -type d | sort | tail -50  
  find data/output -maxdepth 3 -type f ... | head -20  
  ```  
- Команда для поиска старых версий файлов:  
  ```bash
  find . -type f \( -iname '*recogniz*' -o -iname '*fingerprint*' -o -iname '*scene_analy*' \) -not -path './.venv/*' -not -path './.git/*' | sort  
  ```  
- Команда для поиска изменений в `recognizer.py`:  
  ```bash
  git log --all -p -- app/core/recognizer.py | less  
  ```
