#### 2. **Запуск полного анализа**
```bash
uv run python /tmp/full_analysis.py
```

После выполнения:

```bash
tail -n 150 output/benchmark_components/full_analysis.txt
```

Ищите:

- **Количество изменений** в `VIRTUAL WINNER CHANGES` (например, `changed=3`).
- **Случаи с маленьким DELTA** (например, `FINAL margin < 0.03`).
- **Какие кандидаты** (например, `84_v33` vs `87_v33`) конкурируют в этих случаях.

---

#### 3. **Ключевые вопросы для анализа**
1. **Сколько случаев меняет BEST?**  
   - Пример: `BEST_WEIGHT=0.10` → `changed=5` (из 262).
   - Это важно для понимания, насколько `BEST` влияет на итог.

2. **Какие кандидаты чаще конкурируют?**  
   - Пример: `84_v33` vs `87_v33` в 90% случаев с `FINAL margin < 0.03`.

3. **Помогает ли BEST в сомнительных случаях?**  
   - Если `FINAL margin = 0.0019` → `BEST advantage = +0.0538`, то `BEST` решает спор.

4. **Какой вес BEST дает наилучшие результаты?**  
   - Проверьте `BEST_WEIGHT=0.05` или `0.10` — где `changed` минимально.

---

#### 4. **Пример анализа вывода**
Если в `SUSPICIOUS CASES` найдётся:

```text
BEST_DIFF=+0.0538 | 84_v33 / 87_v33 | image_123
```

→ Это **реальный случай**, где `BEST` решает спор.

Если в `VIRTUAL WINNER CHANGES`:

```text
BEST_WEIGHT=0.10 changed=5
```

→ `BEST` влияет на 5 из 262 случаев — это **незначительно**, но важно.

---

#### 5. **Рекомендации**
- Если `BEST` влияет на **менее 5% случаев**, то:
  - Возможно, `BEST` не является ключевым фактором.
  - Стоит проверить **другие метрики** (например, `E/C/S`).
- Если `BEST` влияет на **более 10% случаев**, то:
  - Нужно улучшить **логику выбора** в сомнительных случаях.
  - Возможно, стоит добавить **взвешенную сумму** `FINAL + BEST_WEIGHT × BEST`.

---

#### 6. **Дополнительный анализ**
Если `BEST` влияет на **менее 5% случаев**, но есть **много сомнительных случаев** (например, `FINAL margin < 0.03`), то:
- Стоит проверить **качество данных** (например, `image_123`).
- Возможно, нужно **усилить обучение модели** на таких случаях.
