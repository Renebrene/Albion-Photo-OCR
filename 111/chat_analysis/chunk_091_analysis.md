### 🔧 **Решение проблемы: фильтрация клиентов не работает из-за неправильного сравнения строк**

#### 📌 **Причина**
В текущем коде используется `casefold()`, который не корректно обрабатывает кириллические символы. Например:
- `ОЗОН`.casefold() → `"озон"`
- `"Ozon"`.casefold() → `"ozon"`

Эти строки не совпадают, поэтому фильтр не срабатывает.

---

### ✅ **Исправление**

В файле `app/web/components/photos.py` измените сравнение клиентов на `lower()`:

```python
# Вместо:
record_client.casefold() == selected_client.strip().casefold()

# Сделайте:
record_client.lower() == selected_client.strip().lower()
```

---

### 📌 **Пояснение**
- `lower()` преобразует **все символы в нижний регистр**, включая кириллицу.
- Это гарантирует, что `"ОЗОН"` и `"Ozon"` будут считаться одинаковыми.

---

### 🔄 **Проверка**
1. Перезапустите сервер:
   ```bash
   uv run python -m app.web.main
   ```
2. Выберите клиента (например, **ОЗОН**).
3. Проверьте логи:
   ```text
   [PHOTO REFRESH CALL] search_query= '' results= 100
   [PHOTO GRID EXECUTED] files= 100
   ```

Если всё работает, фотографии будут фильтроваться по клиенту.

---

### 🚀 **Дополнительные шаги (если нужно)**
Если фильтрация всё ещё не работает:
1. Убедитесь, что `PHOTO_RECORD_INDEX` содержит записи для выбранного клиента.
2. Проверьте, что `STATE.selected_client` корректно сохраняется (например, `"ОЗОН"` или `"Ozon"`).
3. Убедитесь, что в БД клиенты хранятся в правильном формате (например, `"ОЗОН"`).

---

### 📌 **Вывод**
Исправление сравнения на `lower()` решит проблему с фильтрацией клиентов. После этого выбор клиента в интерфейсе будет корректно отображать только его фотографии.
