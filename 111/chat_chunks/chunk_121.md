# В итоге

Я бы зафиксировал новую модель проекта именно так:

**INPUT - оригиналы.**

**OUTPUT - всё производное:**

- SQLite БД
- индексы
- fingerprints
- hashes
- previews
- Qwen JSON
- результаты распознавания
- статусы процессов
- история запусков

А **физическая сортировка фотографий больше вообще не нужна**.

Сортировка:

```text
95_v33
87_v33
78_v33
...
```

становится просто **полем в БД**.

Это даст нам сразу четыре вещи:

1. **Грид начинает работать сразу**, не дожидаясь окончания обработки.
2. **DINO и Qwen работают независимо и параллельно.**
3. **Оригинал никогда не теряется и не дублируется.**
4. **Грид становится фактически live-интерфейсом к базе**, а не просмотрщиком папки.

И это, на мой взгляд, уже правильная архитектура для следующего этапа «Альбион: Фотобаза. Офис», а не очередная оптимизация существующей схемы.
