## Почему так происходит

Наш текущий DINO embedding отвечает примерно на вопрос:

> «Насколько визуально похожи эти две фотографии?»

А нам нужен другой вопрос:

> **«Сняты ли эти фотографии с одной позиции / относятся ли они к одной сцене?»**

И это важное различие.

Например:

```text
33 (13)
33 (14)
33 (15)
33 (16)
33 (17)
```

DINO прекрасно понимает, что это очень близкие изображения:

```text
0.975
0.974
0.963
...
```

Это хороший кандидат на один подслепок.

Но:

```text
Ленина 125 А (7)
33 (30)
Ленина 125-127 А (2)
33 (16)
...
```

попадают в одну огромную группу, потому что для DINO это **одна и та же визуальная среда**.

То есть сейчас DINO правильно определяет **адрес/окружение**, но плохо отделяет **точку съёмки**.

MIN_CLUSTER_SIZE = 2

def normalize_rows(x):
    x = np.asarray(x, dtype=np.float32)

    norms = np.linalg.norm(
        x,
        axis=1,
        keepdims=True,
    )

    norms[norms == 0] = 1.0

    return x / norms

def build_knn_graph(embeddings):
    """
    Создает граф локальных соседей.

    Связь между A и B появляется только если:

    1. B входит в K ближайших соседей A
    2. A входит в K ближайших соседей B
    3. similarity >= threshold

    Это сильно уменьшает эффект chaining.
    """

    similarity = embeddings @ embeddings.T

    n = len(embeddings)

    neighbors = []

    for i in range(n):

        scores = similarity[i].copy()

        # Само изображение исключаем
        scores[i] = -1.0

        indices = np.argsort(scores)[-K:][::-1]

        neighbors.append(set(indices.tolist()))

    graph = [set() for _ in range(n)]

    for i in range(n):

        for j in neighbors[i]:

            if i not in neighbors[j]:
                continue

            score = float(similarity[i, j])

            if score < SIMILARITY_THRESHOLD:
                continue

            graph[i].add(j)
            graph[j].add(i)

    return graph, similarity

def connected_components(graph):
    """
    Находим связные компоненты графа.
    """

    n = len(graph)

    visited = np.zeros(n, dtype=bool)

    groups = []

    for start in range(n):

        if visited[start]:
            continue

        stack = [start]
        visited[start] = True

        group = []

        while stack:

            current = stack.pop()

            group.append(current)

            for neighbor in graph[current]:

                if visited[neighbor]:
                    continue

                visited[neighbor] = True
                stack.append(neighbor)

        groups.append(sorted(group))

    return groups

def split_large_cluster(group, embeddings):
    """
    Дополнительная защита от chaining.

    Если внутри большого компонента есть слабые связи,
    оставляем только локальные плотные связи.
    """

    if len(group) <= 4:
        return [group]

    local = embeddings[group]

    similarity = local @ local.T

    graph = [set() for _ in range(len(group))]

    for i in range(len(group)):

        scores = similarity[i].copy()
        scores[i] = -1.0

        # Локальные соседи внутри компонента
        k = min(3, len(group) - 1)

        indices = np.argsort(scores)[-k:]

        for j in indices:

            if similarity[i, j] < SIMILARITY_THRESHOLD:
                continue

            graph[i].add(int(j))
            graph[j].add(i)

    components = connected_components(graph)

    return [
        [group[i] for i in component]
        for component in components
    ]

def build_groups(embeddings):

    graph, similarity = build_knn_graph(embeddings)

    groups = connected_components(graph)

    final_groups = []

    for group in groups:

        parts = split_large_cluster(
            group,
            embeddings,
        )

        final_groups.extend(parts)

    # Сортируем по размеру
    final_groups.sort(
        key=lambda x: len(x),
        reverse=True,
    )

    return final_groups, similarity

## Но я бы сейчас НЕ переходил к V36 с простым изменением threshold

Главная проблема V35 — **sub_01 слишком большая**.

26 фотографий туда попало потому, что текущий алгоритм делает:

> изображение достаточно близко к centroid → добавить в группу.

Это создаёт эффект **«цепочки»**.

Например:

```text
A близко B
B близко C
C близко D
D близко E
```

но при этом:

```text
A далеко от E
```

А алгоритм всё равно может положить A–E в одну группу.

Для нашей задачи это неправильно.

# Что предлагаю сделать следующим шагом

Нам нужен уже не `V36 threshold`, а **V36 с другим принципом формирования subfingerprint**.

Я бы сделал так:

### 1. Не centroid-only

Вместо:

```python
image → centroid
```

использовать одновременно:

```text
image → centroid
image → ближайшие изображения группы
image → средняя близость к группе
```

То есть фотография может попасть в subfingerprint только если она действительно похожа **на несколько фотографий этой группы**, а не только на её усреднённый центр.

---

### 2. Ввести два порога

Например:

```text
CENTROID_THRESHOLD = 0.90
MEMBER_THRESHOLD   = 0.88
```

Условие:

```text
similarity(image, centroid) >= 0.90
AND
similarity(image, нескольким членам группы) >= 0.88
```

Это должно разорвать часть искусственных цепочек.

---

### 3. Убрать автоматическое присоединение одиночек

Вот этот блок V34/V35 я бы **пока полностью убрал**:

```python
# Маленькие группы присоединяем к наиболее близкой
# существующей группе.
```

Он сейчас потенциально портит структуру.

Если фотография действительно уникальна — **пусть остаётся singleton**.

Для нашей задачи это намного лучше, чем ошибочно объединить её с другой сценой.
