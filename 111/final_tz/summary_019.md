## 3. АРХИТЕКТУРНЫЕ РЕШЕНИЯ  
- **Сессионное хранение данных**:  
  Используется `app.storage.user` для хранения настроек (режим отображения, фильтры) и идентификатора пользователя.  
  Обоснование: позволяет сохранять состояние между запросами и персонализировать интерфейс.  

- **Разделение состояния**:  
  Глобальное состояние (STATE) для общих данных (фото, клиенты), сессионное (app.storage.user) для пользовательских настроек.  
  Обоснование: изолирует данные, упрощает обновление и тестирование.  

- **Хранение настроек в PostgreSQL**:  
  Таблица `user_interface_settings` с JSONB полем для динамических настроек.  
  Обоснование: обеспечивает сохранение данных между сессиями и кросс-устройственный доступ.  

- **Автоматизация для гостей**:  
  По умолчанию гости получают все фильтры активными (все клиенты/адреса) и период "последний месяц".  
  Обоснование: упрощает вход без регистрации и сохраняет консистентность UX.
