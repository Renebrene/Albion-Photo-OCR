## 2. АРХИТЕКТУРА И СТРУКТУРА ПРОЕКТА

### 2.1. Общая структура проекта
Проект организован в виде нескольких пакетов и файлов, которые разделены по функциональности. Основные папки включают:

- `app`: Содержит веб-интерфейс и ядро приложения.
- `scripts`: Скрипты для автоматической обработки данных.
- `data`: Хранение данных проекта.
- `config`: Настройки приложения.
- `docs`: Документация проекта.

### 2.2. Модули и пакеты
- **`app/web`**: Включает компоненты для отображения данных в веб-интерфейсе, включая фильтры, состояние и другие элементы.
- **`app/core`**: Содержит ядро приложения, включая распознаватели (DINO, Qwen), обработчики изображений и утилиты.
- **`scripts`**: Скрипты для автоматической обработки данных, запуска пайплайна, тестирования и других задач.
- **`data`**: Папка для хранения данных проекта, включая изображения, метаданные, результаты обработки.
- **`config`**: Настройки приложения, включая пути, параметры распознавателей.
- **`docs`**: Документация проекта, включая README, CONTRIBUTING и другие informative files.

### 2.3. Архитектурные решения
1. **Виртуальная сортировка в базе данных**: Используется для избежания физического перемещения файлов.
2. **Реактивный интерфейс**: Обновляется в реальном времени через запросы к базе данных.
3. **PostgreSQL**: Хранение метаданных и результатов обработки.
4. **Параллельная обработка**: DINO на CPU и Qwen на GPU для повышения производительности.
5. **Очереди для задач**: Управление задачами обработки изображений.
6. **Динамическое определение путей**: Для гибкости в развертывании.

### 2.4. Основные файлы и их назначение
- **`app/web/state.py`**: Управление состоянием приложения.
- **`app/web/components/filters.py`**: Логика фильтрации данных.
- **`app/web/components/addresses.py`**: Обработка адресов.
- **`app/web/components/clients.py`**: Работа с клиентами.
- **`app/web/components/photos.py`**: Отображение фотографий в гриде.
- **`scripts/daily_pipeline_v01.py`**: Основной скрипт для обработки.
- **`app/core/recognizer.py`**: Распознавание изображений с DINO.
- **`scripts/qwen4b_output_v01.py`**: Обработка с Qwen.
- **`photo_worker.py`**: Worker для обработки в фоне.
- **`config/config.py`**: Настройки приложения.
- **`data/photobase.db`**: База данных.
- **`data/output/daily/`**: Хранение обработанных изображений.

- Оптимизация производительности.
- Логирование ошибок.

### 2.6. Используемые технологии и инструменты
- Python для backend и воркеров.
- PostgreSQL для данных.
- DINO и Qwen для обработки изображений.
- NiceGUI для интерфейса.
- Asyncio для асинхронности.
- ThreadPoolExecutor для параллелизации.
- GPU-ускорение для Qwen.

### 2.7. Структура данных
- **База данных**: Таблицы `photos`, `dino_results`, `qwen_results`, `previews`.
- **Файловая система**: `data/output/daily/` для изображений, `data/metadata/` для JSON-файлов.

### 2.8. Процесс обработки
1. Запрос через веб-интерфейс.
2. Запуск pipeline: DINO → сортировка → Qwen → обновление БД.
3. Обновление интерфейса для отображения результатов.
