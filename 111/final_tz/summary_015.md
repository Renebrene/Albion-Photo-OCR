## 3. АРХИТЕКТУРНЫЕ РЕШЕНИЯ  
- **PostgreSQL как основа данных**:  
  Хранение метаданных, статусов обработки и уникальных `photo_id`.  
- **Пулы подключений**:  
  Использование `psycopg_pool` для эффективного управления подключениями к БД.  
- **Режимы пайплайна**:  
  Управление через таблицу `pipeline_control`, синхронизация через транзакции.  
- **Индексация по виртуальным адресам**:  
  Группировка фотографий по `hybrid_final_id` или `dino_fingerprint` вместо физических путей.  
- **Асинхронная обработка**:  
  Использование `apscheduler` для автоматических запусков, `asyncio` для watcher-режима.  
- **Структура каталогов**:  
  `data/input` — входной буфер, `data/photos` — постоянное хранилище с организацией по дате съемки.
