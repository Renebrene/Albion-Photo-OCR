# Windows-сканер сцен

Утилита рекурсивно находит фотографии, вычисляет SHA-256, pHash/dHash и цветовые признаки, строит сцены тем же алгоритмом, что использовался при замере слепков, и складывает данные в **отдельную локальную SQLite-базу**. Затем отдельной командой копирует до 20 выбранных кадров в новую папку.

- Исходные фотографии только читаются: утилита не перемещает, не переименовывает и не удаляет их.
- Это не `data/jobs.db`, не PostgreSQL и не очередь PhotoBAse.
- Файлы `photo.jpg` и `photo (2).jpg` получают одинаковую подсказку `name_group`, но группировка сцен делается по всему сканируемому дереву: имя файла не является доказательством, что два разных кадра — одна сцена.
- Совпадающие имена в разных подпапках сохраняются как разные группы имён (относительный путь входит в ключ).
- Одинаковые параметры и неизменившиеся `size + mtime` позволяют повторно использовать уже сохранённые хеши. `--force` пересчитывает их заново.
- Читаемые форматы: JPG/JPEG, PNG, WEBP, BMP, TIF/TIFF. Реальное декодирование проверяет Pillow; нечитаемый файл записывается в SQLite с ошибкой и не прерывает всё сканирование.

## Установка на Windows

Нужен Python **3.12 x64** с Python Launcher (`py`). Из корня checkout выполните в PowerShell:

```powershell
py -3.12 -m venv .venv-scene-scan
.\.venv-scene-scan\Scripts\python.exe -m pip install -r tools\scene_scan\requirements.txt
```

Зависимости установятся в изолированное окружение `.venv-scene-scan`; PyTorch, PostgreSQL и модели не нужны. `run_windows.bat` использует это окружение, если оно создано; иначе пытается вызвать системный `py -3.12`.

## Использование

Сканирование всей выбранной папки, включая подпапки. База и CSV вынесены за пределы исходной папки:

```bat
tools\scene_scan\run_windows.bat scan "D:\Фото\Объект" --db "D:\SceneWork\scene_scan.sqlite3" --csv "D:\SceneWork\scan.csv"
```

Сводка выведет `run_id`, количество найденных/читаемых файлов, серий, сцен и выбранных кадров. По умолчанию лимит — 20. Можно задать другой, например `--limit 25`; порог схлопывания почти одинаковых кадров по pHash — `--dedup 6`. Чтобы сравнить отбор без dHash, добавьте `--no-dhash`.

После проверки отчёта экспортируйте медоиды в отдельный каталог **вне исходной папки и её родителей**:

```bat
tools\scene_scan\run_windows.bat export --db "D:\SceneWork\scene_scan.sqlite3" --output "D:\SceneWork\selected"
```

По умолчанию экспортируется последний завершённый scan. Для предыдущего запуска укажите `--run-id 3`. Экспорт **копирует** файлы; повторный запуск пропустит уже скопированный файл с тем же SHA-256. При одинаковых именах добавляется суффикс с хешем; существующий файл с другим содержимым не перезаписывается. Перед копированием исходник повторно проверяется по SHA-256, поэтому изменившийся после scan файл не попадёт в выборку без повторного scan.

## SQLite

База содержит таблицы `roots`, `files`, `scan_runs`, `scan_items`, `exports` и `PRAGMA user_version`. Для каждого исходного относительного пути хранятся имя, нормализованная группа имени, размер/mtime, SHA-256, признаки, ошибка чтения и флаг пропажи. Для каждого scan сохраняются параметры, номер сцены и признак выбранного медоида. Удалённые файлы отмечаются `missing`, прежняя история scan не удаляется.

CSV использует UTF-8 BOM и `;`, чтобы открываться в Excel с русской локалью; в нём перечислены все найденные файлы, их SHA-256, сцена, выбранность и ошибка.

## Ограничение масштаба

Алгоритм считает попарную матрицу pHash и силуэт кластеров; память/время растут примерно квадратично с числом файлов. Поэтому по умолчанию сканер ограничивает один запуск 1000 изображениями и откажется продолжать, если лимит превышен. Его можно поднять через `--max-files` (до 5000), но для больших архивов лучше сканировать отдельные папки/объекты отдельными запусками и базами.
