# Сколько фото нужно для слепка — замер (пункт 4)

**Вопрос владельца:** сколько фотографий достаточно для успешного создания fingerprint — 20, 30, 40? Делались подборки 40–80, фото похожи, кажется, хватит 20–30.

**Решение (владелец, 2026-10-14):** останавливаемся на **20–30 фото** на слепок. Ориентир для новых слепков и для окна управления слепками (пункт 3) — **20–30 фото**; больше брать только для адресов, которые путаются с соседними (в замере — пары 84/87 и 89/90).

**Что было в архиве:** рекомендация без измерений — 30–50 фото на адрес, ориентир ~40; «20–25 уже работает»; «50–80 — отдача уменьшается»; «100+ избыточно»; «40 похожих фото хуже, чем 30–40 разнообразных». **Измеренной кривой «размер подборки → качество» не существовало нигде.**

## Методика

Стенд: `scripts/fingerprint_size_experiment.py`.

1. Для **каждого** адреса `data/input/<адрес>/` берётся подвыборка 20/30/40 фото **шагом по списку** (а не «первые N» — иначе подвыборка окажется одной серией кадров с одной точки).
2. Из подвыборки собирается слепок `<адрес>_v33_s<N>` в **отдельном каталоге** (`SCENE_DATA` указывает на scratch), рабочие `data/fingerprints/` не трогаются.
3. Распознавание корпуса (256 фото, `/home/alexice/Desktop/test`) идёт через `app.cli recognize --json` — только чтение слепков и картинок, **без PostgreSQL и без очереди заданий**, история прогонов в базе не засоряется.
4. Сравнение: вердикт варианта против вердикта рабочего набора по каждому фото.

**Важная поправка методики.** Адрес, у которого фото меньше запрошенного размера, берёт **все** свои фото (адрес 90 — 19 фото, адрес 80 — 37). В первом прогоне такие адреса просто выпадали из набора, и замер показывал эффект *отсутствующих слепков*, а не меньшего размера: «20» выглядело лучше «40» только потому, что в наборе «40» не было адресов 80 и 90. Цифры первого прогона непригодны, ниже — исправленный результат.

Все 18 адресов присутствуют в каждом наборе.

## Ограничения

- **Измерено согласие, а не точность.** Истинной принадлежности фото к адресу для корпуса нет: имена файлов — это названия улиц (`Комарова13`, `Ленина125`), а слепки названы технически (`78_v33`…`95_v33`), автоматической связи между ними не существует. Чтобы считать точность, нужна карта «улица → идентификатор слепка»; её удобно завести в новом справочнике адресов (вкладка «Адреса» в техразделе) — после этого замер можно пересчитать в точность на тех же прогонах.
- Корпус (256 фото, 20 локаций) небольшой: разница в 3–4 фото — это ~1.2 п.п., что близко к границе значимости.
- Адрес 90 (19 фото) во всех вариантах идёт целиком, адрес 80 (37 фото) — целиком в варианте «40».
- Вердикт HYBRID в базе получен на полном наборе слепков, поэтому он «свой» полному набору; сравнение с ним смещено в пользу вариантов лишь постольку, поскольку HYBRID переставляет кандидатов из TOP-5 того же DINO-прогона.

## Что дал этот замер по производительности

Создание слепков — CPU-задача, и она распараллелена (по заданию владельца):

- `app/pipeline/worker.py` теперь по умолчанию гоняет **половину ядер** параллельных сборщиков (12 ядер → 6), каждый берёт задания из SQLite-очереди атомарно, получает свои `cores/builders` потоков torch и не более `min(6, cores/builders)` потоков на CPU-проход дескрипторов; `--workers 1` возвращает прежнее поведение.
- **Замер (12 ядер, 6 слепков по 20 фото):** последовательно **57.4 с** (9.6 с на слепок) → в 6 сборщиков **15.4 с** (2.6 с на слепок), ускорение **3.7×**. Идеальные 6× недостижимы из-за загрузки модели в каждом процессе и конкуренции за память; на длинной серии подборок эффективность растёт.
- Полный пересчёт замера (54 слепка + 4 прогона корпуса) после распараллеливания занял **450.9 с** против 778.5 с у первого, последовательного прогона.

## Как перезапустить

```bash
python scripts/fingerprint_size_experiment.py --dry-run        # план
python scripts/fingerprint_size_experiment.py                  # полный замер
python scripts/fingerprint_size_experiment.py --build-only     # только сборка
python scripts/fingerprint_size_experiment.py --variants 20,30 --limit 3
```

Отчёт и JSON складываются в `data/output/fingerprint_size_experiment/` (каталог в `.gitignore` — это рабочие копии фото и numpy-артефакты объёмом ~1.4 ГБ).
