# Мобильный PWA для PhotoBAse — план работ и визуалы

> **Исторический документ.** План написан до реализации; этапы 1–5 выполнены,
> этап 6 закрыт частично. Актуальное состояние — в
> `docs/mobile_pwa_backend_integration.md` и
> `docs/mobile_pwa_complete_report.md`.

## Контекст

Десктопная версия (Vue/Quasar) уже реализована полностью. Мобильный PWA — **отдельный фронтенд**, переиспользующий тот же FastAPI-бэкенд (`/api/v1/*`). Не меняем десктоп.

## Что уже есть (переиспользуем)

| Компонент | Где | Как используем |
|---|---|---|
| **API endpoints** | `app/api/routes.py` | `GET /v1/photos`, `GET /v1/clients`, `GET /v1/collections`, `POST /v1/favorites`, `GET /v1/auth/me` |
| **Аутентификация** | `app/api/auth.py` | JWT-токены, `/auth/login`, `/auth/me` |
| **БД-схемы** | `schema/` | `photos`, `photo_qwen`, `collections`, `user_favorites` |
| **Правила доступа** | `app/api/routes.py` | роли: Гость / Менеджер / Администратор |

## Что нужно добавить (мобильный фронтенд)

| Компонент | Формат | Стек |
|---|---|---|
| **HTML/CSS/JS** | Отдельный проект | **Vanilla JS + CSS** (без фреймворков) — максимально лёгкий, ~50 КБ |
| **PWA** | `manifest.json`, `sw.js` | Workbox (через CDN или inline), offline-кэш |
| **API-клиент** | JS-модуль | Fetch API, session token (localStorage) |
| **Грид фото** | CSS Grid | Адаптивный, lazy-load, cursor-based pagination |
| **Меню** | Custom drawer (hamburger) | Material Design, ~100 строк CSS |

## Этапы разработки

### Этап 1: Каркас (1-2 дня)

**Цель:** рабочий скелет с навигацией и API-клиентом.

1. Создать структуру проекта:
   ```
   mobile/
   ├── index.html
   ├── manifest.json
   ├── sw.js
   ├── css/
   │   └── main.css
   ├── js/
   │   ├── api.js          # API-клиент
   │   ├── auth.js         # логин/выход
   │   ├── grid.js         # грид фото
   │   ├── menu.js         # бургер-меню
   │   └── main.js         # инициализация
   └── assets/
       ├── logo.png
       └── icons/
   ```

2. Настроить `manifest.json` для PWA:
   - Иконки 192x192, 512x512
   - Theme color, background color
   - Short name: "АЛЬБИОН"

3. Реализовать API-клиент (`api.js`):
   - `fetchPhotos(dateFrom, dateTo, cursor, limit)` → `/api/v1/photos` (cursor-based pagination)
   - `fetchCollections()` → `/api/v1/collections`
   - `addFavorite(photoIds)` → `/api/v1/favorites` (POST body: `{photo_ids}`)
   - `removeFavorite(photoId)` → `/api/v1/favorites/{photo_id}` (DELETE)
   - `login(name, password)` → `/api/v1/auth/login` (POST body: `{name, password}`)
   - `getCurrentUser()` → `/api/v1/auth/me` (GET)
   - `fetchSuggestions(query)` → `/api/v1/search/suggestions` (GET `?q=...`)

4. Базовый HTML + CSS Grid:
   - Шапка: бургер + поиск
   - Основной контент: грид
   - Подвал: переключатели
   - Drawer: меню

---

### Этап 2: Грид фото (2-3 дня)

**Цель:** отображение фото с метками и группировкой.

1. **Режим "По датам":**
   - Группировка по датам (заголовок "Сегодня", "15 ноября 2021", ...)
   - Между группами — отступ
   - На фото: название (сокращённое) + дата съёмки

2. **Режим "По папкам":**
   - Группировка по адресам (из `collections`)
   - Заголовок: "Название папки (123)"
   - Синхронизация с десктопными подборками

3. **Lazy loading:**
   - Загрузка превью только при скролле (IntersectionObserver)
   - Превью: `/api/v1/photos/<id>/preview` (MIDDLE, 1280px)
   - Кеш в IndexedDB (до 500 превью)

4. **Hover/long-press preview:**
   - Удержание → enlarged preview + metadata (клиент, бренд, теги)
   - Мобильный: тап → popup с информацией

---

### Этап 3: Подвал и фильтры (1-2 дня)

**Цель:** переключатели режима, количества, периода.

1. **Переключатель режима:**
   - Иконки: "Календарь" (по датам) / "Папка" (по адресам)
   - Состояние сохраняется в localStorage

2. **Количество плиток:**
   - Цикл: 3 / 4 / 5 / 6 колонок
   - CSS Grid: `grid-template-columns: repeat(N, 1fr)`

3. **Период:**
   - Цикл: Вчера → Неделя → 2 недели → Месяц → 2 месяца → Полгода → Год
   - Отправка `dateFrom`/`dateTo` в API

4. **Поиск:**
   - По названию, клиенту, бренду, тегам
   - Debounce 300ms
   - `/v1/photos?search=...`

---

### Этап 4: Избранное и синхронизация (2 дня)

**Цель:** выбор фото, сохранение в избранное, синхронизация.

1. **Выбор фото:**
   - Чекбокс на каждом фото (в режиме "выбор")
   - Кнопка "Выбрать" в шапке → режим выбора

2. **Избранное:**
   - Кнопка "В избранное" → `POST /api/v1/favorites` (body: `{photo_ids}`)
   - **Модель данных:** избранное = collection с `scope='photos'`, `kind='Моя'`. Синхронизация через `collections` + `collection_members` (таблицы десктопа).
   - Раздел "Избранные" в меню → `/api/v1/collections?kind=favorites` → список фото через `/api/v1/collections/{id}/members`

3. **Экспорт:**
   - Выбранные фото → "Поделиться" (Web Share API)
   - **Реализация:** `POST /api/v1/media-links` (scope `upload:write`) → Albion cloud → генерация shareable links
   - Формат: ссылки на файлы + юридические названия (из `photo_qwen`)
   - Мессенджеры: WhatsApp, Telegram, Viber (через Web Share API)

---

### Этап 5: Меню и аутентификация (1-2 дня)

**Цель:** бургер-меню, логин, синхронизация.

1. **Drawer (бургер-меню):**
   - Логотип "АЛЬБИОН"
   - Логин/выход (если не авторизован)
   - "Избранные подборки" → `/api/v1/collections?kind=favorites`
   - "Синхронизировать" → `POST /api/v1/jobs/ingest` (ручной запуск)
   - Настройки (тёмная тема, язык)
   - **Группы адресов** (горизонтальная прокрутка под шапкой): screens, rostov, cities, roads, small → `?group=` query param

2. **Аутентификация:**
   - Экран входа (модальное окно)
   - **Session token** в localStorage (ключ `photobase_token`)
   - **Нет refresh token:** токен хранится до выхода из аккаунта
   - HTTP-заголовки: `Authorization: Bearer <token>`

3. **Роли:**
   - Гость: только просмотр (scope `read`)
   - Менеджер: избранное, экспорт (scopes: `read, collections:write, searches:write, upload:write, photos:write, jobs:read/write`)
   - Администратор: синхронизация, настройки (scope `*`)

---

### Этап 6: PWA и оптимизация (2-3 дня)

**Цель:** офлайн-режим, производительность, управление кешем.

1. **Service Worker:**
   - Кэш API-запросов (стратегия: network-first)
   - Кэш превью SMALL (640px) в IndexedDB (до 500 превью)
   - Обновление при новой версии

2. **Управление кешем:**
   - Индикатор размера кеша в подвале (например, "📦 Кэш: 2.3 МБ")
   - Кнопка "Очистить кеш" в бургер-меню
   - Автоочистка через 7 дней (настраиваемо: 1/3/7/30 дней)
   - Предупреждение при > 10 МБ

3. **Оптимизация:**
   - Lazy loading изображений (IntersectionObserver)
   - WebP для превью (если поддерживается браузером)
   - Minification, tree-shaking

4. **Тестирование:**
   - Mobile devices (iOS Safari, Android Chrome)
   - Offline mode (без сети — кеш работает)
   - Lighthouse scores (PWA, Performance, Accessibility)

5. **Сравнение с десктопом:**
   - Синхронизация избранного (через `collections` + `collection_members`)
   - Синхронизация настроек (через `display` store)
   - Одинаковые API endpoints

## API endpoints (переиспользуем)

| Мобильное действие | Endpoint | Метод |
|---|---|---|
| Загрузка фото (cursor-based) | `/api/v1/photos?dateFrom=...&dateTo=...&cursor=...&limit=...` | GET |
| Превью фото | `/api/v1/photos/<id>/previews/{size}` (size: `small`/`middle`) | GET |
| Поиск (сuggestions) | `/api/v1/search/suggestions?q=...` | GET |
| Поиск (фильтры) | `/api/v1/photos?q=...&brand=...&tag=...&category=...` | GET |
| Избранное (список) | `/api/v1/collections?kind=favorites` → `/api/v1/collections/{id}/members` | GET |
| Избранное (добавить/убрать) | `/api/v1/favorites` (POST: `{photo_ids}`) / DELETE `/api/v1/favorites/{photo_id}` | POST/DELETE |
| Подборки | `/api/v1/collections?kind=favorites` | GET |
| Логин | `/api/v1/auth/login` (POST: `{name, password}`) | POST |
| Текущий пользователь | `/api/v1/auth/me` | GET |
| Синхронизация (ручная) | `/api/v1/jobs/ingest` (POST: `{photo_ids, ...}`) | POST |
| Экспорт (Albion cloud) | `/api/v1/media-links` (POST: `{photo_ids, ...}`) | POST |

## Технические решения

### Lazy loading превью

```javascript
// IntersectionObserver для lazy-load
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target
      img.src = `/api/v1/photos/${img.dataset.id}/preview`
      observer.unobserve(img)
    }
  })
}, { rootMargin: '200px' })

document.querySelectorAll('img[data-id]').forEach(img => observer.observe(img))
```

### Кеш в IndexedDB

```javascript
const DB_NAME = 'albion-mobile'
const STORE = 'previews'

async function cachePreview(id, blob) {
  const db = await openDB(DB_NAME, 1, { upgrade(db) {
    db.createObjectStore(STORE)
  }})
  await db.add(STORE, { id, blob, timestamp: Date.now() })
}

async function getPreview(id) {
  const db = await openDB(DB_NAME)
  return db.get(STORE, id)
}
```

### Cursor-based pagination

```javascript
// API возвращает: { photos: [...], next_cursor: "base64..." }
// На мобильном — infinite scroll: при достижении конца страницы загружаем следующую.

async function loadMorePhotos(cursor) {
  const response = await fetch(`/api/v1/photos?cursor=${cursor}&limit=50`)
  const data = await response.json()
  return { photos: data.photos, nextCursor: data.next_cursor }
}
```

## Риски и ограничения

1. **Превью:** десктоп генерирует MIDDLE (1280px), мобильный запрашивает **SMALL (640px)** по умолчанию для экономии трафика.
2. **Офлайн:** Service Worker кэширует **API-запросы + превью** (network-first стратегия). Кеш хранится в IndexedDB.
3. **Кеш:** автоочистка через 7 дней (настраиваемо), кнопка "Очистить кеш" в бургер-меню, индикатор размера в подвале.
4. **Синхронизация:** избранное синхронизируется через общую БД (`collections` + `collection_members`), но без real-time — при входе подтягивается актуальный список.
5. **Экспорт:** Web Share API работает в мобильных браузерах, но не в iOS Safari (только через "Поделиться" → "Сохранить в Files"). Для экспорта используется `POST /api/v1/media-links` (scope `upload:write`).
6. **Cursor-based pagination:** мобильный UI должен корректно обрабатывать `next_cursor` и передавать его при бесконечном скролле.
7. **Группы адресов:** 5 табов (screens, rostov, cities, roads, small) — **через бургер-меню** (не под шапкой), чтобы не загромождать интерфейс.
8. **Текст на фото:** адрес **жирным** шрифтом, дата **обычным** — внизу плитки.
