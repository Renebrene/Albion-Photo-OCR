# Albion: выгрузка медиа и ссылки

**Статус на 2026-10-17:** код этапа 6 реализован и покрыт тестами, но
интеграция выключена, пока не заданы `ALBION_UPLOAD_URL` и `ALBION_API_KEY`.
Реальный endpoint и ключ владельцем ещё не переданы, поэтому фактическая
загрузка в Albion не проверялась. Это не «готовая облачная функция»: без env
API отвечает 503, а UI показывает предупреждение.

## Контракт, который поддерживает PhotoBAse

PhotoBAse рассчитан на **отдельный ограниченный upload endpoint** Albion,
который не использует браузерную админ-сессию и CSRF:

```http
POST $ALBION_UPLOAD_URL
X-API-Key: $ALBION_API_KEY
Content-Type: multipart/form-data

file=<binary>, ttl_days=90
```

Ожидаемый ответ (допускается также `{"links": [{...}]}`):

```json
{"url": "https://...", "expires_at": "2027-01-15T10:00:00Z", "object_key": "..."}
```

Требования к endpoint:

- ключ передаётся только заголовком, не в query string;
- ссылка абсолютная `http(s)` и без встроенных учётных данных;
- `expires_at` — ISO-8601; если поле отсутствует, PhotoBAse считает срок от
  момента загрузки по `ALBION_LINK_TTL_DAYS`;
- 401/403 — ключ отклонён, 413 — файл слишком велик, 429 — лимит частоты
  (по возможности с `Retry-After`).

Если у Albion появится только старый upload через админ-сессию + CSRF, этот
код использовать нельзя: понадобится прокси/новый endpoint на стороне Albion.

## Конфигурация

Переменные читаются процессом API и worker из `~/.config/scene-fingerprint.env`:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ALBION_UPLOAD_URL` | полный URL upload endpoint | пусто (выключено) |
| `ALBION_API_KEY` | секрет ограниченного API-аккаунта | пусто (выключено) |
| `ALBION_LINK_TTL_DAYS` | срок ссылки, 1…3650 | 90 |
| `ALBION_UPLOAD_TIMEOUT` | таймаут одного HTTP-запроса, сек | 120 |

Ключ не пишется в БД, логи, ответы API и сообщения об ошибках. Для включения
нужно добавить значения в env, перезапустить `scene-api` и `scene-worker` и
проверить, что `GET /api/v1/media-links` возвращает `"configured": true`.

## Схема и поток

`schema/039_media_links.sql`:

- добавляет `MEDIA_EXPORT` в CHECK типа `job_queue`;
- создаёт `media_links`: владелец, вид и ID медиа, provider, статус
  `PENDING`/`READY`/`FAILED`/`EXPIRED`, URL, object key, безопасная ошибка,
  `job_id`, создание/завершение/истечение;
- инвариант: `READY` невозможен без URL и `expires_at`;
- индексы по владельцу, медиа, сроку и статусу.

Поток:

1. `POST /api/v1/media-links` (scope `upload:write`) проверяет формат ID,
   наличие фото/видео в реестре и конфигурацию провайдера.
2. Для каждого элемента создаётся `PENDING`-строка; если у этого владельца уже
   есть действующая `READY`-ссылка на тот же файл, она переиспользуется.
3. В очередь ставится job `MEDIA_EXPORT`; `media_links.job_id` связывает строку
   с job. Загрузка выполняется только worker'ом, не в HTTP handler.
4. Worker (`app/cloud/export.py`) читает оригинал только на чтение, вызывает
   Albion и ставит `READY`/`FAILED`. При ошибке в `error_message` попадает
   безопасный текст без пути, ключа и внутренних адресов.
5. `GET /api/v1/media-links` (scope `jobs:read`) по умолчанию отдаёт только
   действующие `READY`-ссылки текущего пользователя; `all=true` — все владельцы
   и только для Администратора (`*`/`users:manage`), иначе 403;
   `include_unready=true` — также `PENDING`/`FAILED` (для диалога прогресса).
6. `expire_stale()` лениво переводит просроченные `READY` в `EXPIRED` при
   чтении; просроченные строки не выдаются API.

## UI

- Кнопка **«Облако»** в панели выбранных фото и в карточке видео; доступна
  ролям с `upload:write` (Администратор/Менеджер), не Гостю.
- Диалог показывает `PENDING` со спиннером, затем `READY` с копируемым URL или
  `FAILED` с безопасной причиной; опрос идёт каждые 2 с, но не дольше ~5 минут.
- Панель **«Мои ссылки»** в настройках отображения; Администратору в
  техническом разделе дополнительно показываются «Ссылки Albion» всех
  владельцев. Обе панели скрывают просроченные ссылки.

## Ограничения и риски

- Реальная интеграция с Albion не проверялась: нет endpoint/ключа. Тесты
  используют мок HTTP-ответа.
- Сервер не удаляет объект из Albion по истечении срока: он только помечает
  ссылку `EXPIRED`. Удаление/отзыв должен обеспечивать Albion.
- Нет отдельного scope `links:write`; используется `upload:write`, чтобы не
  расширять матрицу ролей до появления реального контракта.
- Повторный клик по тому же файлу до завершения первой загрузки создаёт вторую
  `PENDING`-строку (переиспользуются только готовые ссылки). Это осознанный
  компромисс; при необходимости добавить уникальность/дедупликацию.
- Ограничение размера задаёт Albion (413). PhotoBAse не режет оригинал и не
  перекодирует его перед upload.
- **Имя файла в облаке не подчиняется настройке скачивания** (решение
  владельца 2026-10-23): `app/cloud/export.py` отправляет зарегистрированное
  исходное имя, а отображаемое имя ссылки определяет Albion. «Юридическое имя
  (итерация)» действует только для прямого скачивания и ZIP.

## Откат

1. Убрать `ALBION_UPLOAD_URL`/`ALBION_API_KEY`, перезапустить сервисы — новые
   загрузки выключаются, существующие ссылки остаются в БД.
2. Остановить worker, чтобы он не обрабатывал `MEDIA_EXPORT`.
3. Выполнить rollback из шапки `schema/039_media_links.sql`: вернуть прежний
   CHECK `job_queue` без `MEDIA_EXPORT`, затем `DROP TABLE public.media_links`.
4. Удалить `app/cloud/`, `CloudLinkButton.vue`, `MediaLinksPanel.vue` и
   соответствующие маршруты/тесты, если функция отменяется полностью.
