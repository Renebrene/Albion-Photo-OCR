# HYBRID — Technical Architecture

## 1. Назначение HYBRID

HYBRID является вторым этапом распознавания после DINO.

HYBRID не выполняет самостоятельное распознавание изображений.

Его задача — получить сохранённые результаты DINO для полного DINO BATCH, проанализировать TOP-5 кандидатов и последовательность фотографий и сформировать окончательный вердикт по каждому `photo_id`.

Основной поток:

DINO
→ PostgreSQL DINO RESULTS
→ HYBRID
→ PostgreSQL HYBRID RESULTS

HYBRID не изменяет исходные фотографии.

---

## 2. Источник данных HYBRID

Единственным входом HYBRID является PostgreSQL.

HYBRID получает:

- `batch_id`;
- сведения о DINO BATCH;
- `photo_id`;
- соответствующий `dino_run_id`;
- TOP-1 … TOP-5;
- оценки кандидатов;
- `dino_score`;
- `dino_second_score`;
- `dino_margin`;
- другие данные DINO, сохранённые в PostgreSQL.

HYBRID не читает исходные фотографии.

HYBRID не использует `source_path` для распознавания.

HYBRID не запускает DINO повторно.

HYBRID не использует SUBFINGERPRINTS.

---

## 3. Связь HYBRID с DINO BATCH

Каждый запуск HYBRID относится к конкретному `dino_batches.batch_id`.

HYBRID не формирует собственный набор фотографий.

Набор фотографий определяется DINO BATCH.

Следовательно:

DINO `batch_id`
→ фиксированный набор `photo_id`
→ сохранённые DINO results
→ HYBRID RUN

HYBRID не добавляет и не удаляет фотографии из входного BATCH.

---

## 4. Условие запуска HYBRID

HYBRID может начать обработку только после того, как соответствующий DINO BATCH получил:

`status = 'DONE'`

Состояния:

- `PENDING` — HYBRID не запускается;
- `RUNNING` — HYBRID не запускается;
- `FAILED` — HYBRID не запускается;
- `DONE` — BATCH разрешён как вход HYBRID.

`DONE` означает, что все `dino_runs` данного BATCH успешно завершены.

Наличие отдельных завершённых DINO runs не является основанием для запуска HYBRID.

HYBRID не работает с частично завершённым DINO BATCH.

---

## 5. PostgreSQL как контрольная точка

PostgreSQL является источником истины для перехода:

DINO → HYBRID

Перед созданием HYBRID RUN система проверяет:

1. существует ли `batch_id`;
2. какой у BATCH `run_type`;
3. имеет ли BATCH статус `DONE`;
4. совпадает ли `total_count` с количеством фотографий BATCH;
5. совпадает ли `completed_count` с `total_count`;
6. отсутствуют ли `PENDING` или `RUNNING` DINO runs;
7. существует ли DINO результат для каждого `photo_id`.

Если хотя бы одно условие не выполнено, HYBRID RUN не начинает обработку.

---

## 6. HYBRID RUN

`HYBRID RUN` — отдельная сущность PostgreSQL, представляющая один запуск алгоритма HYBRID на одном завершённом DINO BATCH.

Каждый HYBRID RUN имеет собственный идентификатор:

`hybrid_run_id`

HYBRID RUN связан с:

- одним `dino_batch_id`;
- фиксированным набором DINO results этого BATCH.

Один DINO BATCH может иметь несколько HYBRID RUN.

Пример:

DINO BATCH #1
→ HYBRID RUN #1

DINO BATCH #1
→ HYBRID RUN #2

Оба HYBRID RUN используют одни и те же сохранённые DINO results.

---

## 7. Состояния HYBRID RUN

HYBRID RUN использует состояния:

- `PENDING`;
- `RUNNING`;
- `DONE`;
- `FAILED`.

Переход:

`PENDING → RUNNING → DONE`

или:

`PENDING → RUNNING → FAILED`

HYBRID RUN не переходит в `RUNNING`, если соответствующий DINO BATCH не имеет состояния `DONE`.

---

## 8. Фиксация входа HYBRID RUN

После создания HYBRID RUN его входом является конкретный `dino_batch_id`.

DINO BATCH после состояния `DONE` не изменяется.

Поэтому повторный запуск HYBRID на том же BATCH использует тот же набор DINO results.

HYBRID RUN не создаёт новый DINO BATCH.

HYBRID RUN не изменяет существующие `dino_runs`.

HYBRID RUN не изменяет `dino_candidates`.

---

## 9. Результат HYBRID

Для каждого обработанного `photo_id` HYBRID сохраняет отдельный результат.

Результат содержит как минимум:

- `photo_id`;
- `dino_batch_id`;
- `dino_run_id`;
- исходный лучший DINO кандидат;
- окончательный HYBRID кандидат;
- изменение решения;
- исходную оценку;
- итоговую оценку;
- итоговый margin;
- информацию о соседях;
- статус;
- время обработки;
- сообщение об ошибке при наличии.

Конкретная SQL-структура этих данных определяется отдельной схемой PostgreSQL.

---

## 10. История HYBRID

История HYBRID хранится отдельно от истории DINO.

DINO сохраняет свои `dino_runs`.

HYBRID сохраняет свои `hybrid_runs` и результаты каждого запуска.

Существующий HYBRID RUN не перезаписывается новым запуском.

Повторный запуск создаёт новый `hybrid_run_id`.

Это позволяет сравнивать результаты разных запусков HYBRID на одном и том же DINO BATCH.

---

## 11. Повторный запуск HYBRID

Завершённый DINO BATCH может использоваться повторно.

Повторный запуск HYBRID:

- использует тот же `dino_batch_id`;
- использует сохранённые DINO results;
- не запускает DINO;
- не читает исходные фотографии;
- создаёт новый `hybrid_run_id`;
- сохраняет новую историю результатов.

Таким образом:

DINO BATCH #1
→ HYBRID RUN #1
→ результаты

DINO BATCH #1
→ HYBRID RUN #2
→ результаты

DINO BATCH #1 остаётся неизменным.

---

## 12. FORCE_RERUN DINO

`FORCE_RERUN` относится к DINO, а не к HYBRID.

При FORCE_RERUN создаётся новый DINO BATCH и новые `dino_runs`.

После успешного завершения новый DINO BATCH получает:

`status = 'DONE'`

После этого он может стать входом отдельного HYBRID RUN.

Старый DINO BATCH при этом не изменяется.

---

## 13. Порядок обработки внутри HYBRID

HYBRID получает полный фиксированный набор фотографий конкретного DINO BATCH.

Последовательность фотографий определяется внутри этого BATCH.

Она используется для анализа соседей и серий.

HYBRID работает с сохранёнными TOP-5 DINO кандидатами.

Основной источник решения:

DINO TOP-5
+
анализ последовательности и соседей.

SUBFINGERPRINTS в новом HYBRID не используются.

---

## 14. Граница HYBRID → PREVIEW

После формирования окончательного HYBRID вердикта результат записывается в PostgreSQL.

PREVIEW является отдельным механизмом.

Он может использовать:

- `photo_id`;
- окончательный HYBRID ID;
- данные, необходимые для формирования отображения.

Цепочка:

DINO BATCH DONE
→ HYBRID RUN
→ HYBRID VERDICT в PostgreSQL
→ PREVIEW
→ GRID

PREVIEW не является частью HYBRID.

GRID не является частью HYBRID.

---

## 15. Основной принцип

PostgreSQL является источником истины для всех переходов между этапами.

DINO отвечает за получение первичного результата распознавания.

HYBRID отвечает за окончательный вердикт на основании сохранённых результатов DINO.

PREVIEW отвечает за подготовку отображения после появления HYBRID вердикта.

Ни один следующий этап не должен определять готовность предыдущего этапа по наличию файлов на диске.
