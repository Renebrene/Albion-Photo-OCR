# Превью: вес и влияние сжатия/разрешения (2026-10-22)

Замер на 583 фото текущего корпуса и на 20 исходниках `test/*.JPG`
(средний исходник ~4,3 МБ).

## Что лежит сейчас

| Файл | Размер стороны | Средний вес | Всего на 583 | Прогноз на 57 000 |
|---|---:|---:|---:|---:|
| SMALL | 320 px | **23 КБ** | 13 МБ | **1,3 ГБ** |
| MIDDLE | 1280 px | **292 КБ** | 166 МБ | **16,6 ГБ** |

## Рекомендация

1. **SMALL оставить 320 px.** В плитках грида он уже используется на пределе;
   256 px даёт мизерную экономию (≈0,26 ГБ на 57k), но заметно мылит
   превью на экранах с высокой плотностью.
2. **MIDDLE перевести на q85 при 1280 px.** Это −21 % (≈3,5 ГБ на 57k) без
   изменения разрешения. Риск для QWEN минимален: кроп щита по-прежнему
   режется из оригинала; MIDDLE используется только как fallback, когда
   щит не найден (≈8 % фото).
3. **Разрешение MIDDLE не уменьшать до 1024 без отдельного замера.** Экономия
   ещё ≈4,5 ГБ, но fallback-кадры QWEN могут потерять мелкий текст. Если
   уменьшать, то сначала прогнать 50–100 fallback-фото и сравнить поля
   QWEN с текущими.
4. **Управление без правки кода:** `SCENE_PREVIEW_QUALITY` (по умолчанию 90).
   Уже существующие превью не перезаписываются; новый параметр действует
   на новые/пересоздаваемые файлы.

## Как проверить на своём корпусе

```bash
# текущее распределение
find data/preview/small -type f -printf '%s\n' | awk '{s+=$1;n++} END {print n, s/n}'
find data/preview/middle -type f -printf '%s\n' | awk '{s+=$1;n++} END {print n, s/n}'
```

Для смены качества на новых фото:

```ini
SCENE_PREVIEW_QUALITY=85
```

Перезапустить `scene-preview-worker`. Существующие 583 превью останутся
q90, пока их не пересоздать (например, при полном сбросе и повторном
инспектировании).
