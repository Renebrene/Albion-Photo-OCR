## Порядок

1. **Albion** — выпускает токены с правами и принимает загрузки. Без этого
   клиенты проверить нечего.
2. **Photobase** — первый клиент: проверка связи, выгрузка фото/видео, ссылки.
3. **Демо-сайт** — второй клиент, но со своей задачей: перенести внутреннее
   хранилище сайта на Albion параллельно локальному, с переключателем.

Пункты 2 и 3 не зависят друг от друга и могут идти одновременно после 1.

**Статус (2026-10-20):** все три задания реализованы. Перед запуском
демо-сайта примените миграцию `backend/migrations/migrate_media_external_storage.py`
(см. `03_demo_site_storage.md` и `doc/albion-storage.md` в репозитории сайта);
Photobase и Albion миграций не требуют.

## Общий принцип

Файлохранилище — единственный владелец прав. Оно выпускает токен, хранит только
его SHA-256 и метаданные (имя, права, папка). Клиент не имеет логина/пароля и не
ходит в браузерную сессию: только `X-API-Key` в заголовке. Клиент называет папку,
хранилище проверяет, что токену она разрешена, принимает файл по тем же правилам,
что и веб-интерфейс, и возвращает обычную публичную ссылку.

Механизм намеренно не привязан к Photobase: тот же контракт использует демо-сайт
и сможет использовать следующий проект.

## Термины

- **Токен** — `alb_` + 48 hex, показывается один раз при выпуске.
- **Права (scopes)** — `download`, `upload`, `delete`, `*`.
- **Привязка к папке** — `folder_id` в метаданных токена; запись только туда.
- **TTL** — срок жизни ссылки в представлении клиента. Файл в Albion не удаляется
  по TTL: у хранилища нет такой политики. TTL нужен Photobase, чтобы помечать
  ссылку истёкшей и при необходимости перевыпускать её.

## Что НЕ входит в этот пакет

- Публичный вход в Albion по токену вместо сессии для людей.
- Автоматическое удаление файлов по TTL.
- Синхронизация существующих файлов Photobase/демо-сайта в Albion (backfill).
- Изменение браузерной админки Albion, кроме CLI выпуска токенов.
