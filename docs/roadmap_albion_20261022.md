## 3. Принципы

1. **Сначала доступ и сохранность, потом ML и оптимизации.**
2. **Один этап — одна ветка — один проверенный деплой.**
3. **Backup перед миграцией и destructive-операцией.**
4. **Секреты не в git и не в логах.**
5. **Обратная совместимость:** старые API/идентификаторы живут до отдельного
   решения о breaking change.
6. **Никаких тестов на рабочей БД.**
7. **Метрики до оптимизации, замер после.**

## 5. Интеграции с продуктовой линейкой

### «Диск» — первый приоритет

Код выгрузки в PhotoBase уже есть (`/v1/media-links`, `MEDIA_EXPORT`, настройки
`ALBION_*`), но реальный контракт не проверен: токены/папка не заданы.

План:

1. Контрактные тесты `/api/v1/integration/verify`, `/upload`, `/files/<id>`.
2. Проверить 401/403/404/413/429/507, absolute URL, отсутствие credentials.
3. Решить семантику TTL: PhotoBase хранит `expires_at`, Диск файл не удаляет.
4. Идемпотентность повторной выгрузки, retry, отзыв ссылки.
5. Заморозить контракт перед миграцией Диска JSON→SQLite→S3.

### «Сайт» — только после бизнес-решения

Прямого контракта нет. Нужно решить, нужен ли сайту доступ к фото/адресам
PhotoBase или только к «Диску». Без решения не реализовывать.

### «Мониторинг» и «Локатор» — адреса и геоданные

Единого мастер-справочника адресов нет: PhotoBase — 95, Мониторинг — 96,
Сайт — 682 конструкции. Нужно выбрать источник истины и правило синхронизации
до любых интеграций. Локатор может обогащать координатами, но такого требования
в ТЗ пока нет.

## 8. Риски плана

| Риск | Митигация |
|---|---|
| Смена паролей/БД ломает вход или интеграции | сначала backup, staging, список потребителей |
| TLS/прокси ломает CORS/WebSocket | точные origins, проверка login/upload |
| Хэширование токенов завершает старые сессии | backfill `sha256` для существующих, тест |
| pgvector расходится с FAISS | dual-write, сверка count/checksum, recall |
| GPU OOM | batch-лимиты, очередь, CPU fallback |
| Address master вызывает конфликт продуктов | сначала регламент, потом код |
| 57k не влезает в текущий диск | отдельный расчёт preview/DB/backup до старта |
