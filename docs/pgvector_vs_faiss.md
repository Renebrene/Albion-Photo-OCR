# pgvector или FAISS: сравнение для PhotoBase

Дата: 2026-10-22

## Что есть сейчас

DINO строит 768-мерный CLS-эмбеддинг; он нормализуется и кладётся в
FAISS `IndexFlatIP` рядом с `metadata.json` в `data/fingerprints/<id>`.
Поиск — точный перебор внутри одного слепка.

## Чем pgvector лучше

| Критерий | FAISS (сейчас) | pgvector |
|---|---|---|
| Транзакционность | файлы вне БД: индекс и metadata могут разойтись | эмбеддинг и метаданные в одной транзакции |
| Фильтры | нельзя отфильтровать SQL-условиями внутри поиска | `WHERE` по адресу/клиенту/дате вместе с ANN |
| Восстановление | нужен отдельный backup файлов; checksum вручную | попадает в `pg_dump` и restore |
| Репликация/несколько API | файлы надо синхронизировать между узлами | реплика БД даёт эмбеддинги автоматически |
| Обновление/удаление | перестройка файла, риск осиротевших записей | обычный `INSERT/UPDATE/DELETE` |
| Наблюдаемость | размер и версия — по файлам | SQL-запросы, count, отставание |
| Масштаб | точный `IndexFlatIP` = O(N) на запрос | HNSW/IVFFlat: миллионы векторов, ANN |
| Эксплуатация | своя логика загрузки/выгрузки индекса | обычный PostgreSQL, знакомый backup |

## Чем FAISS остаётся лучше

- Нулевая нагрузка на PostgreSQL и меньше размер БД.
- Нет расширений и отдельной миграции.
- На 25 слепках и 583 фото разница в скорости незаметна.
- Точный поиск без приближения (pgvector HNSW — приближённый, нужен recall-тест).

## Что важно для нас

1. **Не заменять одномоментно.** Сначала dual-write: DINO пишет и в FAISS,
   и в `photo_embeddings(photo_id, embedding vector(768))`.
2. **Сравнить Recall@5** на текущем корпусе: pgvector-поиск должен находить
   те же TOP-5, что FAISS. Только после этого переключать чтение.
3. **HNSW** (`vector_cosine_ops`) для скорости; на 583–57 000 векторов
   подходит и `ivfflat`, но HNSW проще настраивать.
4. **Расширение** `CREATE EXTENSION vector` требует прав суперпользователя;
   в миграции это отдельный шаг.
5. **Откат** — флаг чтения FAISS/pgvector; файлы FAISS не удалять до
   подтверждения recall.
6. **Выигрыш для 57k** появится в фильтрах и в backup: эмбеддинги будут
   восстанавливаться вместе с БД, а не отдельным набором файлов.

## Вывод

Для локальной сети и 57 000 фото FAISS ещё рабочий вариант, но pgvector
даёт транзакционность, фильтры, SQL-наблюдаемость и единый backup.
Рекомендуется пилот с dual-write и проверкой recall, без удаления FAISS до
подтверждения.
