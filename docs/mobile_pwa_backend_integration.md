# Мобильный PWA — интеграция с реальным бэкендом (порт 8010)

**Дата:** 2026-11-21
**Статус:** ✅ Подключено к рабочему API PhotoBAse

---

## Как теперь работает

Мобильный PWA раздаёт **сам бэкенд** по адресу `/mobile/` на том же origin,
что и API (`SCENE_API_PORT=8010`). Отдельный сервер и CORS не нужны:

```
http://<host>:8010/mobile/
https://albion-base.cloudpub.ru/mobile/     # снаружи, через TLS-туннель
```

- Запросы к `/api/v1/*` — same-origin, `Authorization` заголовком;
- кука сессии (`HttpOnly`) ставится при входе и принимается сервером для
  GET/HEAD — поэтому `<img src="/api/v1/photos/<id>/previews/small">`
  авторизуется без отдельного токена в query;
- desktop SPA по-прежнему отдаётся с `/` и не затронута.

---

## Вход

Демо-режим удалён. Единственный источник учётных данных — база PhotoBAse
(`public.users`, пароль сверяется со `scrypt`-хэшем):

```
POST /api/v1/auth/login   {"name": "...", "password": "..."}
→ 200 {"token": "...", "user": {user_id, name, role, ...}}
→ 401 {"detail": "invalid credentials"}
→ 429 при блокировке после серии неудач (SCENE_LOGIN_LOCKOUT)
```

Токен хранится в `localStorage.photobase_token`; сессия восстанавливается
через `GET /api/v1/auth/me` (`{"user": ... | null, "auth_enabled": true}`).

## Контракты API, на которые переведён клиент

| Что | Endpoint | Ответ |
|---|---|---|
| Фото (курсорная пагинация) | `GET /photos?limit=100&cursor=…&sort=date&order=desc` | `{items: [...], next_cursor, total}` |
| Дни съёмки (фасет) | `GET /photos/dates?date_mode=capture&date_from=…&date_to=…&group=…` | `{items: [{date, photos, sample_photo_id}], total}` |
| Фильтры фото | `q`, `address[]` (`addr:<id>`), `client[]`, `brand`, `tag`, `category`, `date_from`, `date_to`, `date_mode=upload\|capture`, `collection_id`, `group=screens\|small\|rostov\|roads\|cities` | |
| Превью | `GET /photos/{photo_id}/previews/small` (или `middle`) | изображение, `Cache-Control: public, max-age=3600` |
| Подборки | `GET /collections` | `{items: [{collection_id, name, scope, members, …}]}` |
| Состав подборки | `GET /collections/{id}/members?member_type=photo\|address\|client` | `{items: [...]}` |
| Адресная панель | `GET /addresses?group=…&date_mode=capture&date_from=…&date_to=…` | `{items: [{address: "addr:<id>", ids: [...], name, count, period_count, …}]}` |
| Подсказки поиска | `GET /search/suggestions?q=…&group=…` | `{items, layout}`; адресные подсказки — только выбранной группы |
| Избранное | `GET /favorites` / `POST /favorites` `{photo_ids}` / `DELETE /favorites/{id}` | `{collection_id, photo_ids, count}`; GET не создаёт подборку |
| Создать подборку | `POST /collections` `{name, kind, scope}` | `201`; имя «Избранные фото» зарезервировано (`409`) |
| Удалить подборку | `DELETE /collections/{collection_id}` (scope `collections:write`) | `{"deleted": id}`, `404` если нет, `409` для служебного избранного |

## Что показывает UI

**Закладки верхнего уровня** — сетка квадратных плиток (по колонкам подвала):
в «По датам» плитка показывает дату и число фото **за выбранный период**
(превью — первый снимок дня), в «По адресам» — сокращённое название адреса
и число фото **за период** (`period_count` из `/addresses`; запрос уходит
с `date_from/date_to/date_mode`). Смена периода в подвале перезагружает обе
вкладки; открытие адреса применяет тот же период к сетке фото. У подборок
сервер состав за период не считает — плитка подписана «в подборке N».
Внутри открывается сетка фотографий, её **первая плитка — «Назад»** (возврат на
уровень вверх); заголовок шапки тоже кликабелен.

**Закладка «По датам»** — плитки дней **съёмки** из серверного фасета
`GET /photos/dates`: перечислены все реально существующие дни за период
с числом фото (`taken_at`, при его отсутствии `created_at`), превью — снимок
`sample_photo_id`. Раньше дни собирались из первой страницы грида (100 фото):
за год на экране оказывались один-два дня. Тап по дню открывает фото именно
этой даты (`date_from=date_to=день, date_mode=capture`) с пагинацией.

**Пустой период.** Если за выбранный фильтр фото нет, период не расширяется:
показывается сообщение «За вчера и позавчера фото нет» (или «За выбранный
период фото нет») и подсказка «Измените период: ближайший фотоотчёт был
сделан DD.MM.YYYY». Ближайшая дата берётся из фасета `/photos/dates` без
date-фильтра, но с текущими группой и адресами (ближайшая до или после
периода). То же сообщение выводится в корне «По адресам», когда в периоде
нет адресов с фото.

Период в подвале (`Вчера/позавчера … Год`) — **даты съёмки**
(`date_mode=capture`); он же применяется к счётчикам адресов. Фото без
EXIF-даты (73 из ~44 тыс.) в «По датах» не попадают — они доступны через
адреса, подборки и поиск.

**Закладка «По адресам»**:
1. «Подборки адресов» — только `scope='addresses'` из `GET /collections`
   (синхронизированы с десктопом). Photo-подборки и служебное
   «Избранные фото» здесь не показываются: они живут в экране «Избранное».
   Адресная подборка открывается через `members` (`address=addr:…`).
2. «Адреса» — строки панели (`name` — сокращённое название, `count`).
   Плитки-адреса — синие карточки без иконки папки: белое жирное название
   по центру (до 3 строк) и белый счётчик за период. Список рисуется
   порциями по 200 (`ADDRESS_PAGE_SIZE`) с кнопкой «Показать ещё» — это
   позволяет показывать группу до 2000 адресов, не строя весь DOM сразу.
   Если выбрано «Все группы» и адресов больше 200 (`ADDRESS_ALL_LIMIT`),
   вместо общего списка выводится просьба выбрать закладку. Нижняя панель
   выбора адресов загружает данные при открытии (в режиме «По датам» их ещё
   нет) и тоже листается порциями.
   **Поиск привязан к группе:** строка поиска передаёт `group` в `/photos`,
   подсказки — в `/search/suggestions`; адресные подсказки и выдача не
   выходят за пределы выбранной группы. При смене группы активный поиск
   пересчитывается. Тап отправляет
   `address=addr:<id>` по всем поверхностям стороны (`ids`).
3. **Создание подборки адресов** — в сетке подборок последняя плитка
   «➕ Добавить подборку». Пока адреса не выбраны, она неактивна
   («выберите адреса»); у гостя — «нет прав». Мультивыбор папок-адресов
   включается кнопкой «☑» в шапке (она видна и в корне «По адресам») или
   долгим нажатием на плитке; тап отмечает папку, чекбокс — справа
   сверху, счётчик — в подписи плитки. Создание: `POST /collections`
   `{name, scope:"addresses"}` → `POST /collections/{id}/members`
   `{member_type:"address", values:["addr:…"]}`; при ошибке сохранения
   состава пустая подборка удаляется. После успеха выделение снимается.
4. **Удаление подборки** — кнопка 🗑 в правом верхнем углу плитки
   (только у роли с `collections:write`); открывает подтверждение
   «Фотографии останутся в базе», затем `DELETE /collections/{id}` и
   перезагрузка списка. У гостя кнопка не показывается.

**Группы адресов** (5 закладок десктопа) — в бургер-меню; выбор группы
передаётся как `group=` и влияет и на даты, и на список адресов. Добавлен
пункт «Все группы».

**Поиск** — поле под шапкой: `q` с задержкой 350 мс (подстрочный поиск по
описаниям), результаты — сетка фото. Через 250 мс под полем появляются
подсказки `GET /search/suggestions` (теги, клиенты, бренды, категории,
адреса; вместе с вариантом в другой раскладке). Тап по подсказке бренда/
тега/категории/клиента ставит точный фильтр (`brand`/`tag`/`category`/
`client`), адрес ищется текстом. `Esc` и тап вне списка закрывают подсказки.

**Плитка**: сокращённое название (`simple_address` → `legal_address` →
`address` → `filename`) жирным, дата съёмки обычным — снизу плитки.
Превью — SMALL (640 px), `loading="lazy"`; при 404 плитка остаётся серой.

**Мультивыбор.** Режим включается кнопкой «☑» в шапке сетки фото или
долгим нажатием (500 мс) на плитке. В режиме у всех плиток видны пустые
кружки-чекбоксы, тап отмечает/снимает фото, «Все» выбирает загруженную
страницу. Долгое нажатие отменяется только при сдвиге пальца больше 10 px
(дрожание не мешает) и подавляет контекстное меню Android. Нижняя панель:
«❤️» — `POST /favorites`; «📋» — копирование в буфер адресов (без повторов)
и ссылок на фото; «📤» — системное меню «Поделиться» для отправки в
мессенджер (при отсутствии Web Share API текст автоматически копируется);
«✕» — снять выделение и выйти из режима.

**Карточка фото** листается свайпом влево/вправо (циклически) по списку
текущего экрана — дня, подборки, адреса или результатов поиска; счётчик
«N / M» в левом верхнем углу. По бокам — прозрачные стрелки «‹»/«›»;
тап по левой/правой четверти снимка тоже листает. Свайп работает за счёт
`touch-action: pan-y` (вертикальная прокрутка не перехватывается) и
`pointerup` на `window` — жест не теряется, если палец ушёл за оверлей.
Внизу карточки: «❤️ Добавить» / «❤️ Убрать» (переключатель по статусу
фото в избранном; у выбранного — красная заливка), «📤 Поделиться»,
**«⬇️ Скачать»** и **«✕ Закрыть»**. Скачивание — оригинал (`/photos/{id}/original`, scope
`originals`) под именем «юридический адрес (итерация).ext»: итерация —
хвостовое «(N)» исходного имени файла, иначе позиция фото в списке;
запрещённые символы заменяются на `_`. На десктопе то же листание делают
стрелки клавиатуры, `Esc` закрывает.

## Избранное

- **Сердечко в шапке справа** открывает внутреннее избранное — фото-подборку
  пользователя (`GET /favorites` → `collection_id` + `photo_ids`, грид через
  `/photos?collection_id=…`). Кнопка видна всегда; у ролей без
  `collections:write` клик показывает пояснение о правах.
- Над гридом три действия:
  - **⬇️ Скачать** — все фото одним ZIP (`POST /photos/archive`,
    scope `originals`, максимум 500 файлов; имена
    «сокращённый адрес__имя файла»);
  - **📤 В мессенджер** — системное «Поделиться» с нумерованным списком
    «название — файл» и ссылкой на MIDDLE-превью; без Web Share API текст
    копируется в буфер;
  - **🏷 Назвать** — создаёт именованную фото-подборку (`scope:"photos"`)
    из текущего избранного: она появляется в десктопном «Избранном».
    Это снимок на момент сохранения; последующие изменения сердечек в нём
    не отражаются.
- **Именованные подборки** — ниже грида секция «Избранные подборки»:
  все фото-подборки пользователя, кроме служебной `Избранные фото`
  (это те же подборки, что в десктопном «Избранном»). Тап открывает
  подборку, 🗑 удаляет её (фото в базе остаются).
- Данные избранного подтягиваются при входе и по кнопке «Синхронизировать»,
  поэтому сердечки на плитках и в карточке соответствуют сохранённому
  избранному; выход очищает это состояние.
- Служебная подборка `Избранные фото` защищена от удаления: `DELETE
  /collections/{id}` для неё отвечает `409`, а `POST /collections` не даёт
  занять её имя. Так сердечки нельзя стереть, удалив «обычную» подборку.
- `GET /favorites` больше не создаёт подборку: она появляется при первом
  добавлении фото (POST), поэтому чтение не меняет базу.
- Ограничение: ZIP и сообщение включают первые 500 фото (лимит архива);
  при большем избранном в тексте/тосте явно пишется «N из M».

## Обновление PWA

- **Автообновление.** `mobile/js/pwa.js` регистрирует `sw.js` с
  `updateViaCache: 'none'` и не чаще одного раза в сутки (ключ
  `localStorage.photobase_sw_checked_on`; также при возврате на вкладку)
  вызывает `registration.update()`. Новый service worker вызывается с
  `skipWaiting()`, забирает клиентов (`clients.claim()`) — после
  `controllerchange` страница один раз перезагружается. Первая установка
  не перезагружает (контроллера ещё нет).
- **Принудительное обновление.** Бургер-меню → «⬆️ Обновить приложение»:
  проверяет обновление, активирует ожидающий SW, удаляет кэши
  `albion-*` (чужие кэши origin не трогает), сбрасывает дневную отметку
  и перезагружает страницу. Токен сессии в `localStorage` сохраняется.
- Версия кэша: `albion-mobile-v9`.

### Баги, найденные и исправленные во время прогона

1. **Вход падал с `net::ERR_FAILED`, хотя сервер отвечал 200.** Причина:
   service worker перехватывает **все** запросы контролируемой страницы (scope
   ограничивает клиентов, а не запросы), а `networkFirst` вызывал `cache.put`
   на POST — `cache.put` для не-GET бросает TypeError, `respondWith`
   отклоняется, браузер убивает ответ. Неудачный вход (401) проходил, потому
   что не-ok ответы не кэшировались — это и сбивало с толку. Исправлено:
   кэшируются только GET, запись обёрнута в try/catch.
2. **Подпись дня `undefined.20.11`.** Неверная распаковка `dayKey.split('-')`
   (`[, year, month, day]` вместо `[year, month, day]`). Исправлено.
3. **Обновления не доезжали: старый `main.js` из кэша.** Статика отдавалась
   cache-first в SW и `max-age=3600` с сервера, а имена файлов без хеша.
   Исправлено: network-first для оболочки, `Cache-Control: no-cache` для
   `/mobile/js/` и `/mobile/css/`, `fetch(..., {cache:'no-cache'})` в SW.
4. **Карточки адресов с серой пустой плашкой и строки «0 фото».** Превью
   выводится только при наличии фото; адреса без фото скрыты.
5. **Служебное избранное удалялось как обычная подборка.** `DELETE
   /collections/{id}` теперь отвечает `409` для `Избранные фото`, имя
   зарезервировано; в «По адресах» остаются только `scope='addresses'`.
6. **Избранное не подтягивалось после входа и оставалось после выхода.**
   `doLogin()` вызывает `loadFavoriteIds()`, `doLogout()` очищает сердечки,
   именованные подборки, поиск и выбранные адреса.
7. **Превью не попадали в свой кэш.** Ветка `/previews/` в `sw.js` стояла
   после `/api/` и была недостижима; теперь проверяется первой, поэтому
   `clear-previews` действительно очищает превью прошлой выборки.
8. **Периоды были на день длиннее подписи.** «Неделя» включала 8 дней,
   «Вчера/позавчера» — ещё и сегодняшний; границы пересчитаны по
   календарным дням. Листание превью в «Избранном» работает так же, как в
   остальных сетках.
9. **Панель выбора адресов не реагировала на тап.** Её обработчик висел на
   `#content`, а сама панель лежит вне него; клик по адресу/подборке не
   срабатывал. Обработчик перенесён на `#addressPickerContent`; панель
   догружает адреса из режима «По датам» и листается порциями.
10. **Поиск игнорировал активную группу.** Запросы `/photos` и
   `/search/suggestions` теперь получают `group`, поэтому подсказки и
   результаты не показывают адреса/фото других закладок.

## Известные ограничения

1. **Офлайн-кэш.** Service Worker контролирует страницы `/mobile/` и
   перехватывает все их запросы, включая `GET /api/*` и превью — для
   всех них используется network-first с кэшем на случай offline. Кэш
   приватный (ответы под токеном) и очищается по сообщению
   `clear-private-cache` при выходе из аккаунта. Не кэшируются POST/PUT/DELETE.
   Десктопная SPA не попадает под этот SW (другой scope клиентов).
2. **Период фильтруется по дате съёмки** (`date_mode=capture`), а дни
   группируются по `taken_at || created_at` — фото без EXIF-даты попадёт в
   день загрузки. «Неделя» — 7 календарных дней включительно;
   «Вчера/позавчера» — ровно два дня, сегодняшний не входит.
3. **Подборки клиентов и фото-подборки** в «По адресам» не показываются
   (фильтр `scope === 'addresses'`): фото-подборки доступны в «Избранном»,
   клиентские — отдельная ветка отображения.
4. **Второй адрес/бранд** и теги QWEN в списке фото не приходят (в выборке
   `/photos` их нет) — карточка показывает адрес, клиента, бренд, категорию
   и дату.
5. **Экспорт** — ссылки на MIDDLE-превью через системное «Поделиться»;
   очередь облачных ссылок Albion (`/media-links`) не подключена.
6. **Офлайн только для чтения:** изменения (избранное, подборки) не ставятся
   в очередь и не синхронизируются после восстановления сети.
7. **Lighthouse (2026-11-22):** Performance/Accessibility/Best Practices/PWA —
   100, SEO 92 (индексация закрыта намеренно). Оставшиеся необязательные
   замечания и команда запуска — `docs/mobile_pwa_lighthouse.md`.
