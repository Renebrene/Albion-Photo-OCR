# Роли, scopes и доступ (PhotoBAse)

**Статус:** описание текущего контракта. Источник истины — `app/api/auth.py`
(`ROLE_SCOPES`, `require_scope`, `resolve_principal`); поведение закреплено
тестами `tests/test_role_scopes.py` и `tests/test_api_auth.py`.

## Как устроена авторизация

Два вида credentials в `Authorization: Bearer <token>`:

1. **Сервисный токен** из `SCENE_API_TOKENS` (`token:scope1|scope2`, `*` = все).
2. **Токен пользовательской сессии** (`app.users.database`, таблица `sessions`);
   scopes выводятся из роли пользователя через `ROLE_SCOPES`.

**Fail-closed.** Проверка включена по умолчанию: `SCENE_AUTH_REQUIRED`
по умолчанию `1`. Отключить можно только явно (`SCENE_AUTH_REQUIRED=0`) для
доверенной локальной разработки. Невалидный/неизвестный токен даёт `401`;
нехватка scope — `403`; публичный `/api/health` открыт всегда.

Если БД недоступна при проверке сессии, запрос **не** превращается в `500`:
credential считается недействительным и возвращается `401` (fail-closed).

## Матрица ролей

| Роль | Scopes |
|---|---|
| **Администратор** | `*` (всё) |
| **Менеджер** | `read`, `collections:write`, `searches:write`, `upload:write`, `jobs:read`, `jobs:write`, `addresses:write`, `originals`, `videos:read`, `videos:write`, `videos:download` |
| **Гость** | `read` |

## Гостевой доступ

- Учётная запись «Гость»: логин **гость** (без учёта регистра), пароль
  **альбион**. Подсказка с этими данными показана на экране входа.
- Настройки отображения гостя **не сохраняются** ни в localStorage, ни на
  сервере; у Менеджера и Администратора — сохраняются за пользователем.
- Сменить пароль: `scripts/set_password.py Гость`; после этого обновите
  подсказку в `frontend/src/App.vue` и `frontend/src/pages/Help.vue`.

Неизвестная роль трактуется как `read`.

### Что означает каждый scope

| Scope | Что открывает |
|---|---|
| `read` | Метаданные фото/видео, превью, статистика, список адресов/клиентов, клиентские алиасы (чтение), jobs-статусы там, где объявлено `read`. |
| `originals` | Скачивание оригиналов фото и ZIP-архива выбранного (`/v1/photos/.../original`, `/v1/photos/archive`). Проверка пути — внутри `SCENE_ORIGINALS_ROOTS`. |
| `upload:write` | Загрузка файлов (`POST /v1/upload`). |
| `jobs:read` | Просмотр заданий очереди. |
| `jobs:write` | Запуск/остановка рабочих заданий: DINO/HYBRID/QWEN, INGEST, сборка слепков, pause/resume/cancel/requeue, автоматизация, выгрузка QWEN-модели из памяти. |
| `settings:write` | Изменение провайдера/модели QWEN, Base URL и API-ключа. Только Администратор; Менеджер по-прежнему запускает QWEN-задания, но не управляет учётными данными провайдера. |
| `addresses:write` | Справочник адресов, привязка слепков к адресам, импорт адресов. |
| `collections:write` | Подборки и нормализация клиентов (alias→canonical). |
| `searches:write` | Сохранённые поиски и умный поиск по загруженному медиа. |
| `videos:read` / `videos:write` / `videos:download` | Метаданные/теги, transcode/trim/storyboard, скачивание оригиналов и производных видео. |
| `users:manage` | Каталог пользователей (только Администратор). |

## Политика по ролям (решения владельца)

- **Гость** — read-only: фильтры, сетка фото/видео, переключение режимов.
  Не может скачивать, не видит окна редактирования карточек, недоступны
  подборки, поиск по медиа, сохранение настроек сайта и техраздел.
- **Менеджер** — рабочий пользователь: всё, что у Администратора, кроме
  технического раздела (администрирование пользователей). Может запускать и
  вести рабочие задачи пайплайна и скачивать медиа.
- **Администратор** — всё, включая техраздел.

## Изменения 2026-10-16 (этап 0 стабилизации)

- Роли **Менеджер** добавлен scope `jobs:write` (владелец: «Да, рабочие jobs» —
  менеджер запускает и ведёт рабочие задачи пайплайна).
- Проверка сессии переведена в fail-closed: при недоступной БД возвращается
  `401`, а не `500`.

## Закладки изолированы по пользователю (schema/034, код — этап «8»)

Подборки (`collections`) и сохранённые поиски (`saved_searches`) теперь
принадлежат пользователю, который их создал:

- список/создание/удаление идут от имени текущего пользователя; чужой
  `collection_id`/`search_id` недоступен на изменение (404);
- фильтр грида по чужой подборке даёт пустую страницу (не подтверждает
  существование id);
- сервисный токен и открытый режим (аутентификация выключена) сохраняют общий
  доступ — `user_id = NULL` означает «системная» запись;
- Гость (`read`) видит только свои (пустые) подборки и не может создавать:
  кнопки создания/удаления в UI скрыты, `POST/DELETE` вернут `403`;
- закреплено тестами `tests/test_api_collections.py::test_collections_are_isolated_per_user`
  и `tests/test_api_searches.py::test_saved_searches_are_isolated_per_user`.

Наследованные записи без владельца приписаны встроенному «Администратору»
миграцией `schema/034_owner_isolation.sql` (колонки не удаляются, откат —
`DROP INDEX IF EXISTS idx_collections_user`).

## Скачивание: решение 2026-10-16

**Менеджер скачивает оригиналы.** Роли добавлен scope `originals` (вместе с
уже имевшимися `videos:read/write/download`): владелец подтвердил, что
«Менеджер отличается от Администратора только техразделом», значит скачивание
фото и ZIP ему доступно.

Единственная роль без скачивания — **Гость**: у него нет ни `originals`, ни
видео-scopes. Инвариант закреплён тестами
`tests/test_video_api.py::test_manager_may_download_and_guest_may_not` и
`tests/test_role_scopes.py::test_guest_gets_no_download_scopes` (раньше на этом
месте стоял тест «у Менеджера нет `originals`» — он отменён этим решением).

### Управление провайдером QWEN (закрыто 2026-10-17)

`PUT /v1/qwen/settings` и `PUT /v1/qwen/model` требуют отдельный scope
`settings:write`; его имеет только Администратор (`*`). Менеджер сохраняет
`jobs:write` для запуска QWEN и может выгрузить модель из памяти
(`POST /v1/qwen/unload`, операция без изменения ключей), но не может менять
провайдера, Base URL, API-ключ или выбранную модель. Это закрывает риск
раскрытия/изменения облачных учётных данных рабочей ролью.
