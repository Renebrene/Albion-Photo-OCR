# Подсказки строки поиска и проверка раскладки

Дата: 2026-10-17

## Что делает

Пока пользователь набирает строку поиска, под полем появляются подсказки из
уже существующих значений базы:

- теги (`photo_qwen.tags`),
- клиенты (`photo_qwen.client`),
- бренды (`photo_qwen.brand`),
- категории (`photo_qwen.category`),
- **адреса** (`address_directory.legal_address` / `simple_address`) — они
  участвуют в подсказках наравне с тегами.

Совпадение — подстрока (`ILIKE '%…%'`) или триграммное сходство (`pg_trgm`),
поэтому слегка перепутанное слово тоже находит реальный тег. Сначала идут
совпадения с начала строки, затем по сходству, затем по частоте.

## Проверка раскладки

Если в текущей раскладке найдено меньше трёх значений, строка переворачивается
в другую раскладку по карте ЙЦУКЕН↔QWERTY (`app/core/layout.py`). Когда
перевёрнутый вариант что-то находит, в меню появляется пункт
«Похоже, набрано в другой раскладке» с исправленным запросом — клик
подставляет его и сразу применяет поиск.

Пример: `rjvfhjdf` → `комарова` → «Комарова 13».

## API

`GET /v1/search/suggestions?q=<термин>&limit=8` (scope `read`):

```json
{
  "items": [{"value": "Рязанка", "kind": "brand", "uses": 2}],
  "layout": {"query": "комарова", "items": [{"value": "Комарова 13", "kind": "address", "uses": 1}]}
}
```

`items` — прямые совпадения; `layout` — `null`, когда раскладка не при чём.

## Поиск по адресу

Предикат `q` в `list_photos` дополнен полями `legal_address` и
`simple_address`, поэтому клик по подсказке адреса действительно фильтрует
грид (раньше сравнивался только технический id распознавания).

## UI

- Поле поиска: `@update:model-value` обновляет подсказки (задержка 250 мс),
  `@clear` и опустошение поля сразу перезапускают грид без кнопки «Поиск».
- Стрелка/Enter — обычный поиск; клик по подсказке подставляет значение,
  закрывает меню и применяет фильтр.

## Склеенные подсказки и подсветка панелей (29.10.2026)

Одно значение может быть клиентом, брендом и тегом одновременно («Байков»).
В меню это ОДНА строка с подписью «тег · бренд» (п. 4 задания), и выбор
применяет **все** роли сразу: раньше строка показывала две роли, а фильтр
ставился только по первой, и часть фото пропадала.

### Группа — область, а не альтернатива

Кнопки верхней панели («Видеоэкраны», «Область», …) задают **область**
выборки. Раньше их адреса уходили в тот же `OR`, что бренд и тег, поэтому в
режиме объединения любой структурный фильтр при активной подборке возвращал
всю подборку — «поиск по тегам не работает». Теперь группа передаётся в
`_photo_where(..., group_addresses=…)` отдельным условием `AND`, а выбранные
в панели адреса остаются альтернативой внутри неё.

Пример: подборка «Видеоэкраны» (95 адресов), выбор тега «Байков» —
до исправления возвращалась вся подборка (50 047 фото), после отдельного
AND-фильтра и поиска подстрокой по тегам — **354 фото** во всём временном
интервале (режим «Все даты»). «Байков» встречается не только как точный тег,
но и в «А.М. Байков», «Байков Андрей Матвеевич», «Год Байкова» и других
вариантах; точное равенство пропускало большинство совпадений. Для этого же
примера свободный текстовый поиск показывает 359 фото — он включает и другие
поля QWEN (например, описание), поэтому счётчики могут немного отличаться.

### Подсветка списков

Списки адресов и клиентов/брендов не сужаются поиском: строки, у которых
есть фото по запросу, подсвечиваются жёлтой полосой (`.panel-match`).
Данные для подсветки даёт `GET /v1/search/matches` (scope `read`):

```
GET /v1/search/matches?q=Байков&date_from=…&date_to=…&date_mode=capture&group=screens
{"names": ["Байков", "СК10", …], "addresses": ["56_v33", "58_v33", …]}
```

- `names` — клиенты, бренды и теги фото, подходящих под запрос; значения
  приводятся к каноническому имени через `client_aliases`, как в панели.
- `addresses` — адресные слепки тех же фото; панель сверяет их со своим
  полем `fingerprints`.

Считается тем же предикатом `_photo_where`, что и грид, поэтому подсветка не
расходится с выдачей. Запрос тяжёлый (полный проход по корпусу, 3–4 с),
поэтому он не блокирует страницу: грид рисуется сразу, подсветка приходит
следом. Ответ кешируется (`app/api/cache.py`, TTL 10 с).
