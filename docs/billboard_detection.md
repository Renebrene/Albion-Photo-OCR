# Детекция рекламных щитов (фоновая ветка)

Дата: 2026-10-17

## Место в архитектуре

Основной пайплайн не меняется:

```
INGEST → PREVIEW → DINO → HYBRID → грид
```

Параллельно, в той же очереди PostgreSQL, идёт детекция щитов:

```
PREVIEW (готов) → BILLBOARD_DETECT → кроп из оригинала → photo_regions
                                              ↓
                      QWEN_PHOTO (описание) анализирует кроп вместо кадра
                                              ↓
                                        photo_qwen → грид
```

Ключевое: **отдельного задания распознавания кропа нет.** Пайплайн описания
(QWEN_PHOTO) сам выбирает вход — кроп щита, если опция включена и crop найден,
иначе полный кадр. Выключение в «Распознавание» игнорирует даже ранее сохранённый
crop и возвращает QWEN на MIDDLE preview; файлы crop остаются cache и не удаляются.
Это отдельная опция от generic QWEN `qwen_crop` (центральное обрезание кадра).
Результат, как и раньше, пишется в `photo_qwen`, поэтому грид, поиск,
нормализация клиентов и статистика работают без изменений.

Обе тяжёлые операции выполняются только в worker. HTTP-процесс (API) модель не
загружает. Оригиналы не изменяются; кроп — производный файл.

## Задание очереди

| Тип | Payload | Что делает |
|---|---|---|
| `BILLBOARD_DETECT` | `{photo_id}` | Детекция самого большого щита, кроп, запись региона |

Повторная постановка при активном задании не создаёт дубль (partial unique
index `ix_billboard_active_dedup`).

## Как работает детекция

`app/billboard/detector.py`:

1. Фото декодируется и уменьшается до `billboard_max_side` (по умолчанию
   1920 px) — **только для поиска**.
2. YOLO-World (`data/models/yolov8s-worldv2.pt`) предсказывает боксы.
3. Дубли одной цели (IoU > 0.6) схлопываются, остаётся **самый большой бокс**
   (текущий контракт: один щит на фото).
4. Бокс пересчитывается в координаты **оригинала** и расширяется на
   `billboard_padding` (доля от размера бокса).
5. Кроп вырезается из оригинала в полном разрешении (`app/billboard/pipeline.py`,
   `write_crop`): временный файл → проверка PIL → `os.replace`.
   Мелкий текст баннера не теряется.

Кропы: `data/crops/<photo_id>/crop_01.jpg` (каталог в `.gitignore`).

**Кроп временный.** Он существует только до успешного распознавания: после
`photo_qwen.save_success` файл удаляется вместе с пустым каталогом
(`discard_crop`). При ошибке QWEN кроп остаётся для повторного запуска.
Повторное распознавание при отсутствующем файле заново детектирует щит и
создаёт кроп по требованию. Накопленные кропы прошлых версий удаляются
скриптом `scripts/cleanup_crops.py` (есть `--dry-run`).

## Как выбирается вход описания

`run_photo()` в `app/qwen/processor.py`:

1. `ensure_crop(photo_id)` — если регион уже найден, возвращает его кроп;
   если нет, детекция выполняется **на месте** (на случай, когда фоновое
   задание ещё не отработало).
2. Кроп найден → модель получает кроп без центрального обрезания, с лимитом
   стороны 2048 px (мелкий текст читаем), промптом про рекламный щит и
   `repeat_penalty` 1.1 против зацикливания на мелком шрифте.
3. Кропа нет / детектор недоступен / ветка выключена → анализируется полный
   кадр (MIDDLE preview), как раньше.

Промпт кропа извлекает **description, client, brand, category, tags**.
`address` намеренно не запрашивается: на баннере это обычно юридический адрес
рекламодателя из мелкого шрифта (модель на нём зацикливалась).

## БД

Таблица `public.photo_regions` (миграция `schema/040_billboard_detection.sql`):

- `bbox_*` — координаты в системе оригинала;
- `score`, `detector` — уверенность и версия детектора;
- `crop_path`, `crop_width/height` — производный кроп;
- `qwen_*` — историческое поле прежней отдельной ветки распознавания кропа.
  Новый пайплайн эти колонки не пишет; результаты описания живут в
  `public.photo_qwen`, как для любого фото.

`public.photo_qwen` перезаписывается новым описанием, прежнее сохраняется в
`photo_qwen_history` (штатная механика).

## Настройки (app_settings, меняются без перезапуска)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `billboard_detect` | `1` (`SCENE_BILLBOARD_DETECT`) | включить детекцию/кроп-вход; редактируется переключателем «Использовать crop рекламного щита для QWEN» во вкладке «Технический раздел → Распознавание» |
| `billboard_score` | `0.4` | порог уверенности детектора |
| `billboard_padding` | `0.02` | отступ вокруг бокса |
| `billboard_max_side` | `1920` | сторона копии для детекции |
| `billboard_model` | `data/models/yolov8s-worldv2.pt` | чекпоинт |
| `billboard_classes` | billboard / digital billboard screen / advertising screen | классы YOLO-World |

Модель загружается один раз на процесс worker. Нужен `ultralytics`
(`pip install -e ".[billboard]"` или `uv pip install ultralytics`).

## Запуск

1. Применить миграцию `schema/040_billboard_detection.sql` (уже применена в
   рабочей БД).
2. Убедиться, что `ultralytics` доступен интерпретатору worker.
3. Перезапустить `scene-worker`.
4. Новые фото: детекция встаёт автоматически после успешного `PHOTO_PREVIEW`;
   описание QWEN само возьмёт кроп.
5. Существующий корпус: поставить `QWEN_PHOTO`, чтобы описания обновились с
   кропов (прежние уйдут в историю).

## Ограничения и риски

- Zero-shot YOLO-World иногда принимает машину/фасад за щит. Тогда описание
  будет сделано по ошибочному кропу. Лечится fine-tune с негативами
  (этапы 1–2 `scripts/billboard_zero_shot.py`) или порогом `billboard_score`.
- Порог 0.4 выбран по замерам на корпусе и примерах.
- Детекция — CPU-инференс (GPU занят сборкой fingerprint); ~0.01–0.05 с на
  кадр после загрузки модели.
- Ветка не запускается для видео.

## Откат

1. Выключить ветку: `billboard_detect = 0` (описание вернётся к полному кадру).
2. При необходимости откатить миграцию (SQL в шапке
   `schema/040_billboard_detection.sql`), убрать ветку `BILLBOARD_DETECT`
   из worker.
3. Удалить `data/crops/` (производные файлы).
