# Полная чистка результатов и прогон заново

Дата: 2026-10-24

Два способа привести базу к нулю:

| Способ | Что с результатами | Когда нужен |
|---|---|---|
| `scripts/purge_results.py` | удаляются безвозвратно | результаты не нужны совсем |
| `scripts/archive_results.py` | переносятся в `*_archive` (schema/049), рабочие таблицы очищаются | нужен чистый старт, но история распознавания должна остаться |

Ниже — общий порядок; особенности архивации отмечены отдельно.

## Когда это нужно

Результаты распознавания накопились от нескольких прогонов и частичных
инспекций (корпус доезжал по частям), и хочется получить одну согласованную
картину по всему пулу. Тогда результаты очищаются, а регистрации и `photo_id`
остаются: инспектор не пересчитывает ID файлов, а прогон заново проходит
превью → DINO → HYBRID → QWEN → «Уточнение».

## Что удаляется, а что остаётся

| Удаляется | Остаётся |
|---|---|
| `dino_batches`, `dino_runs`, `dino_candidates` | `photos` с их `photo_id` и `source_path` |
| `hybrid_runs`, `hybrid_results` | `video_assets`, постеры и производные видео |
| `photo_qwen`, `photo_qwen_history` | `photo_previews` (готовые превью — это вход, а не результат) |
| `photo_regions` и файлы кропов (`data/crops`) | `fingerprints`, `address_directory`, привязки слепков |
| | ручные утверждения адресов (`photo_address_overrides`) |
| | коллекции, поиски, пользователи, настройки |
| | `run_history` — журнал прогонов (остаётся как аудит) |

Кропы удаляются всегда (они восстанавливаются вместе с описаниями), превью —
только с флагом `--previews`: без него PREVIEW-стадия достроит недостающие и
не будет пересчитывать уже готовые 34 тысячи кадров (~2 часа CPU).

## Порядок

```bash
set -a && . ~/.config/scene-fingerprint.env && set +a

# 0. Бэкап — обязателен, операция необратима.
.venv/bin/python scripts/backup_db.py

# 1. Посмотреть, что будет удалено (ничего не меняет).
.venv/bin/python scripts/purge_results.py

# 2. Очистить.
.venv/bin/python scripts/purge_results.py --confirm
```

Скрипт отказывается работать, пока идёт прогон «Обновление базы» или
выполняются задания INGEST_DIR / PHOTO_PREVIEW / DINO_BATCH / HYBRID_RUN /
QWEN_PHOTO / REFINE. `--force` снимает этот запрет — нужен, например, когда
параллельно достраиваются превью: их очистка не касается.

Дополнительные флаги: `--previews` (удалить и превью с файлами),
`--no-crops` (не трогать файлы кропов), `--json` (машинный отчёт).

## Вариант с архивом (рекомендуемый)

```bash
set -a && . ~/.config/scene-fingerprint.env && set +a
.venv/bin/python scripts/migrate.py                  # схема 049: таблицы архива
.venv/bin/python scripts/archive_results.py          # отчёт, ничего не меняет
systemctl --user stop scene-preview-worker scene-billboard-worker
.venv/bin/python scripts/archive_results.py --confirm --force
systemctl --user start scene-preview-worker scene-billboard-worker
```

Что делает `--confirm`:

1. отменяет незавершённые задания прогона (превью, детекция щита, DINO,
   HYBRID, QWEN, «Уточнение») — строки заданий остаются в журнале со статусом
   `CANCELLED`;
2. переносит в `*_archive` батчи и прогоны DINO с кандидатами, HYBRID с
   результатами, описания QWEN с историей, регионы-кропы; рабочие таблицы
   очищаются, счётчики идентификаторов перезапускаются с 1;
3. удаляет превью (строки и файлы) и кропы (файлы и строки регионов).

Остаются: `photos` с их `photo_id`, `video_assets`, `fingerprints`,
справочник адресов, ручные утверждения, коллекции, настройки, `run_history` и
журнал заданий. Флаги `--keep-previews`, `--keep-crops`, `--keep-jobs`
оставляют соответствующую часть на месте.

Воркеры превью и детекции щита на время операции останавливают: иначе они
дописывали бы файлы уже после очистки. `--force` нужен именно потому, что
перед остановкой воркеров их задания ещё числятся выполняющимися.

Проверка после операции:

```sql
SELECT count(*) FROM public.photo_previews;     -- 0
SELECT count(*) FROM public.dino_runs;          -- 0
SELECT count(*) FROM public.dino_runs_archive;  -- сколько было
SELECT count(*) FROM public.fingerprints;       -- без изменений
```

## Прогон заново

1. Технический раздел → «Распознавание»: проверить, что «Запускать QWEN в
   «Обновлении базы»» включён, если описания нужны в этом прогоне.
2. Технический раздел → «Уточнение»: этап доступен, если QWEN участвует или
   в базе есть описания; он пойдёт последним этапом прогона.
3. Кнопка «Обновление базы» на главной → указать папку пула → запустить.

Что произойдёт по стадиям: INGEST увидит уже зарегистрированные файлы (только
доставит новые), PREVIEW достроит недостающие превью, DINO пройдёт по всем
фото с превью, HYBRID рассортирует их разом, затем QWEN (самый долгий этап:
локальная модель тратит ~2.7 с на кадр, то есть ~40 часов на 57 тысяч фото) и
последним — «Уточнение».

QWEN можно ускорить двумя способами: выключить его в настройках (прогон
пройдёт инспектор → превью → DINO/HYBRID, а описания дозаполняются за
период) или включить «Запускать QWEN автоматически» в планировщике — тогда он
стартует параллельно сортировке и общее время прогона сокращается.

## Откат

Откат — восстановление из дампа, снятого перед очисткой:

```bash
pg_restore --clean --if-exists -d photobase_ingest_test \
    /path/to/photobase_ingest_test_<штамп>.dump
```

Отдельного «отката очистки» нет: удалённые результаты восстанавливаются
только из бэкапа, зато их можно получить и заново — повторным прогоном.
