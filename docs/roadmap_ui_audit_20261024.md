# Аудит UI и план исправлений (2026-10-24)

## Как проводился

Три независимых прохода по разным слоям (грид; сторы и API-клиент; компоненты и
рендер) плюс проверка каждой находки по коду: смотрели, нет ли рядом
компенсации, из-за которой поведение на самом деле корректное. Находки, где
компенсация есть, в список не попали (см. «Что проверено и не подтвердилось»).

Найдено 36 пунктов: 2 — P1, 24 — P2, 10 — P3. Три из них — регрессии наших
недавних правок (помечены «наша правка»), они идут в работу первыми.

Область: `frontend/src` (страницы, компоненты, сторы, api-клиент). Бэкенд
затрагивается только там, где нужен новый контракт (сортировка выдачи).

## План работ

Порядок — по риску и по цене. Каждый этап: правка → тесты → коммит в `main`,
наблюдаемое изменение описывается в отчёте.

**Этап 1. P1 — доступ и сессии.**
1. `session.js`: различать «не авторизован» и «не удалось спросить»; экран входа
   с сообщением и повтором при сбое `/v1/auth/me`; не запускать `afterAuth` с
   чужими/общими настройками отображения.
2. `api/client.js`: поколение кэша картинок, чтобы blob не переходил между
   сессиями.

**Этап 2. Данные и гонки (P2).**
3. Серверная сортировка выдачи (`sort`/`order` + keyset-пагинация) — снимает
   «вставку в середину», заодно упрощает клиент.
4. `Promise.allSettled` и отдельная ошибка панелей.
5. `syncLoaded()` — обход всего загруженного набора.
6. `pollToken` в опросе прогона; `generation` в `stores/videos.js`.
7. Флаги остановки в опросах (`FingerprintsList`, `SystemMonitor`,
   размонтирование грида).

**Этап 3. UX-состояния (P2).**
8. Подтверждения и блокировки: удаление адреса, удаление подборки, сохранение
   правки слепка, «Скачать», диалоги сохранения.
9. Прогресс сжатия видео, не привязанный к выделению; «Обновить» в мониторинге.
10. `getJson` с причиной ошибки; честные пустые состояния (`LastRun`).
11. «Интервал» и «Время запуска» в автоматизации — по blur/Enter.
12. `RefineStage`: сохранение тумблера сразу.

**Этап 4. Производительность (P2/P3).**
13. Виртуализация: видео-галерея, справочник адресов.
14. `AuthImage`: рабочий `lazy`, blob только при ошибке прямого пути.
15. Мемоизация выделения и частей строки; дебаунс записи в `localStorage`.
16. Материализация адреса фото колонкой, обновляемой HYBRID (панель адресов и
    подвал перестают считать адрес на лету).

**Этап 5. Долги (P3).**
17. Синхронизация фильтров с URL; «Выбрать всё по фильтру»; имя файла при
    скачивании выделенных; `combine` в сохранённом поиске; удаление мёртвого
    кода (`selectAllCurrent`, `scheduleSelectionPersist`).

## Что проверено и не подтвердилось

Эти места выглядят подозрительно, но компенсация в коде есть — трогать не
нужно:

- `stores/photos.js` — гонки выдачи закрыты счётчиком `generation` и токенами
  запросов (`loadFacets`, `facetsRequest`), ответы на устаревшие запросы
  отбрасываются;
- `pages/PhotosGrid.vue` — сериализация догрузки через `pageLoadPromise`;
- `stores/display.js` — `flush()` на `pagehide`, настройки не теряются при
  закрытии вкладки;
- серверный merge выделения в `PUT /v1/selection` (клиент не перетирает чужой
  выбор);
- `applyNlResults` — предупреждение об усечении есть;
- дедупликация по `photo_id` при догрузке страниц и лимит `limit <= 100` —
  соблюдены.

## Процесс

Каждый пункт обсуждаем перед реализацией: что меняем, какие есть варианты,
что увидит пользователь, как проверяем. После согласования — правка, тесты
(pytest для бэкенда, vitest для фронтенда), сборка SPA, коммит и пуш в `main`,
затем следующий пункт.
