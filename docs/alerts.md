# Алерты технического раздела (v1)

Дата: 2026-10-22

## Где видны

Технический раздел → **Система**. `GET /api/v1/system` возвращает
`alerts`, `gpus`, `network.rate_mbps`, `security`; UI рисует баннеры
алертов, карточки GPU/сети и счётчик неудачных входов. Опрос — раз в 2 с.

## Пороги (env)

| Переменная | По умолчанию | Смысл |
|---|---:|---|
| `SCENE_ALERT_CPU` | 90 | порог CPU, % |
| `SCENE_ALERT_CPU_WINDOW_SEC` | 300 | окно «устойчивой» нагрузки |
| `SCENE_ALERT_RAM` | 75 | порог RAM, % |
| `SCENE_ALERT_DISK` | 75 | порог диска, % |
| `SCENE_ALERT_TEMP` | 80 | порог температуры, °C |
| `SCENE_ALERT_GPU` | 90 | порог загрузки/VRAM GPU, % |
| `SCENE_ALERT_NETWORK_MBPS` | 1 | минимальная скорость сети при активных файловых jobs |
| `SCENE_ALERT_NETWORK_LOW_SEC` | 120 | сколько секунд держится низкая скорость |
| `SCENE_LOGIN_FAILURE_LIMIT` | 10 | неудачных входов за окно |
| `SCENE_LOGIN_FAILURE_WINDOW` | 600 | окно подсчёта входов, с |
| `SCENE_REQUEST_LIMIT` | 300 | запросов/мин с одного IP |
| `SCENE_REQUEST_WINDOW` | 60 | окно подсчёта запросов, с |
| `SCENE_TRUST_PROXY` | 0 | доверять `X-Forwarded-For` (только за доверенным прокси) |

## Что проверяется

- **CPU**: ≥ 90 % в 80 % сэмплов за последние 5 минут.
- **RAM**: текущее ≥ 75 %.
- **Диск**: текущий ≥ 75 %.
- **Температуры**: любое чтение ≥ 80 °C.
- **GPU**: утилизация или VRAM ≥ 90 % (если `nvidia-smi` доступен; иначе
  карточка GPU не выводится).
- **Сеть**: ошибки/потери за интервал; скорость ниже 1 МБ/с дольше 2 минут
  при активных `INGEST_DIR`, `PHOTO_PREVIEW`, `BILLBOARD_DETECT` или
  `QWEN_PHOTO`.
- **Вход**: ≥ 10 неудачных попыток за 10 минут (всего или с одного IP).
- **Подключения**: ≥ 300 запросов/мин с одного IP.

## Ограничения v1

- Счётчики входов/запросов живут **в памяти процесса** и сбрасываются при
  рестарте API. Для расследований нужен отдельный durable `audit_log`.
- `X-Forwarded-For` учитывается только при `SCENE_TRUST_PROXY=1`, иначе
  берётся адрес TCP-клиента.
- Алерты не отправляют внешних уведомлений: они видны в техразделе и
  пишутся в journald только как часть ответа API. Для email/Telegram нужен
  отдельный канал.

## Проверка

```bash
curl -fsS -H "Authorization: Bearer <admin>" \
  http://127.0.0.1:8010/api/v1/system | python -m json.tool | head -40
```
