# Технический отчет и рекомендации Gemma

## Стратегия отображения превью (Progressive Loading)
Использование Progressive JPG — это отличный базовый уровень, но для современных систем (особенно на NiceGUI/Vue) я рекомендую комбинированный подход «LOD (Level of Detail)»:

### Progressive JPG vs WebP
Хотя Progressive JPG хорош тем, что картинка появляется «постепенно», формат WebP обеспечивает лучшее сжатие при сопоставимом качестве. Рекомендую использовать WebP как основной формат превью.

### Blur-up эффект
Вместо того чтобы ждать загрузки даже Progressive JPG, сначала отображается очень маленький (например, 50x50 пикселей) сильно размытый (blurred) превью-изображение. Как только основное фото загружается, оно заменяет размытое. Это создает ощущение мгновенной работы интерфейса.

### Кэширование
Внедрение локального кэша в браузере/клиенте для превью, чтобы при повторном просмотре или переключении вкладок изображения не загружались заново.

## Оптимизация прокрутки (Virtual Scrolling)
Если в Гриде сотни или тысячи фото, даже Progressive JPG не спасет от "тормозов" отрисовки DOM-элементов.

### Virtual Scrolling (Виртуализация)
Это технология, при которой в DOM (структуре страницы) находятся только те элементы, которые видны пользователю в данный момент. Когда пользователь скроллит вниз, элементы сверху удаляются из DOM, а новые добавляются снизу. Это позволяет плавно прокручивать бесконечные списки без потери производительности.

### Chunk Loading
Загрузка данных для Грида должна идти "пачками" (например, по 50-100 записей), а не всей базы сразу.

## Исправление ошибки "64 characters"
Эта ошибка часто возникает при попытке сохранить слишком длинный ID или путь в поле базы данных, где установлено ограничение VARCHAR(64).

### Решение
В плане нужно добавить проверку длины при генерации ID. Если транслит + цифры превышают лимит, нужно использовать хеширование (например, MD5/SHA1 части названия) или обрезку с добавлением сокращения (например, ...).

## Резюме и рекомендации для Roadmap
1. **Virtual Scrolling**: Внедрение виртуализации Грида для обеспечения плавной прокрутки больших объемов данных.
2. **LOD Previews**: Реализация "Blur-up" техники (загрузка низкодетальных превью перед высокодетальными).
3. **WebP/Progressive Support**: Приоритизация использования WebP и Progressive JPG в модуле `app/preview/`.
4. **ID Validation**: Добавление логики обрезки/хеширования для обеспечения соответствия ограничению в 64 символа.
