# Отбор кадров в слепок по сценам

**Задача владельца:** слепок должен собираться из 20–30 **разных** кадров, а не
из «первых попавшихся»: у адреса десятки снимков с одной точки, и слепок из них
описывает серию, а не объект. Правила: если условий съёмки всего 2–3 — добирать
фото до 20; если сцен слишком много — брать не больше 30.

**Решение:** отбор вынесен в `app/core/scene_select.py` (без torch — только
картинки и k-means). Его используют скрипт-отчёт, замерный стенд и (следующий
шаг) сама сборка слепка — чтобы правила не разъезжались.

## Как выбираются кадры

1. **Признак кадра.** pHash (64 бита, композиция) + dHash (64 бита, направление
   градиента) + цветовая подпись (42 бита, температура и насыщенность) +
   яркость (одна ось, ×6). Биты — ±1, поэтому расстояние по битовым блокам —
   половина расстояния Хэмминга.
2. **Серии.** Кадры ближе 6 бит по pHash — один «щелчок затвора»; в выборке
   остаётся один представитель серии.
3. **Сцены.** Оставшиеся кластеризуются k-means по составному признаку; число
   сцен подбирается по силуэту (наибольшее k, чей силуэт не хуже 90 % лучшего).
4. **Рабочий диапазон 20–30.** Меньше 20 сцен — дробим мельче (выборка
   равномерно добирается по папке), больше 30 — схлопываем.
5. **Кадр на сцену.** Из каждого кластера берётся медоид — ближайший к центру.

## Сколько сцен в папках (20 папок `data/input`)

```
python scripts/scene_clusters.py --root data/input --json data/output/scenes.json
```

| Сцен нашлось | Папки |
|---|---|
| 2–3 | 65, 86, 88, 90, 91, 92, 93, 94, 95 (9 папок) |
| 4–8 | 79, 80, 87 |
| 17–22 | 64, 78, 81, 82 |
| 26–35 | 83, 84, 85, 89 |

(Числа — для признака с dHash; без dHash разбиение другое: 79 и 83 дают 2 сцены,
а 78 и 85 — 31 и 33.)

Единого «естественного» числа сцен нет: 2…35. По монтажам (собраны скриптом)
«двойки» осмысленны — это сезон или погода (65: лето/зима, 79: солнце/пасмурно),
а большие k на 78/85/89 переразбиты (соседние сцены повторяют одно условие).
Поэтому вместо «истинного» числа сцен и работает рабочий диапазон 20–30.

**Проверка добора.** Если сцен меньше 20, выборка всё равно берёт 20 кадров;
проверено, что они раскладываются по настоящим сценам, а не сваливаются в одну:
65 → 13/7, 79 → 3/5/7/5, 86 → 5/7/8, 91 → 10/10, 80 → 4/4/5/3/2/2, 64 → все 17
сцен покрыты, 81 → 15 из 17.

## dHash: помогает или нет

Первая проверка (выборки, 20 папок, A/B на одних и тех же кадрах):

* выборки совпадают в среднем на **0.49** — dHash меняет около половины кадров;
* силуэт с dHash ниже во всех папках (0.065 против 0.100 у 64, 0.117 против
  0.179 у 79) — но силуэт несравним между разными наборами признаков, это не
  «хуже»;
* монтажи выборок (86, 87) визуального выигрыша не показали.

Решающая проверка — на слепках и корпусе, см. ниже: **с dHash совпадение с
текущими результатами выше** (253 против 248).

## Замер на слепках (корпус 256 фото)

```
python scripts/fingerprint_size_experiment.py --select scene --scene-sets v34,v34nd
```

Стенд собирает для каждого адреса слепок по новым правилам в отдельном дереве
(`data/output/fingerprint_size_experiment/`, рабочие `data/fingerprints/` не
трогаются), с именами `<адрес>_v34` (с dHash) и `<адрес>_v34nd` (без), и
прогоняет корпус `/home/alexice/Desktop/test` через `app.cli recognize`
(только чтение, без PostgreSQL и очереди).

| Набор слепков | Совпало с текущим | Доля | Изменилось фото |
|---|---|---|---|
| сцены, dHash (`_v34`) | 253 / 256 | **98.83 %** | 3 |
| сцены, без dHash (`_v34nd`) | 248 / 256 | 96.88 % | 8 |
| для сравнения: 20 фото шагом (пункт 4) | 253 / 256 | 98.83 % | 3 |
| для сравнения: 30 фото шагом (пункт 4) | 252 / 256 | 98.44 % | 4 |

Изменившиеся фото — только «спорные» адреса: `Ленина125_04, 08` (87 → 84),

Состав слепка по сценам (вариант с dHash): 20 кадров у 79, 80, 81, 86–88,
91–95; 21 у 82; 22 у 78; 26 у 85; 30 у 83, 84, 89; 16 у 90 (в папке всего 19
фото и 16 серий).

## Как воспроизвести

```bash
# отчёт по папкам: сколько серий, сцен, что выбрано
.venv/bin/python scripts/scene_clusters.py --root data/input --json data/output/scenes.json

# слепки по новым правилам + прогон корпуса + сравнение
.venv/bin/python scripts/fingerprint_size_experiment.py --select scene --scene-sets v34,v34nd
```

Отчёт стенда: `data/output/fingerprint_size_experiment/report.md` и `result.json`
(каталог не коммитится — это расходный материал замера).

## Ограничения и что осталось

* **Сравнение идёт с текущими слепками, а не с истиной.** 98.83 % — это
  устойчивость набора (насколько вердикты совпали), а не доказанная точность:
  разметки «правильный адрес» у корпуса нет. Меньше изменений — не всегда лучше,
  но это единственная доступная мера.
* Признак сцены — картинка целиком; людей, машины и вывески он не различает.
  Для адресов, которые путаются с соседними, вопрос решает не отбор кадров, а
  их состав по объекту.
* Яркость в признаке почти не влияет (множители 3…20 меняли число сцен не более
  чем на одну) — оставлена как дешёвая подсказка о свете.
* На больших k (26–35) кластеры повторяются: верхняя граница 30 — это
  компромисс между «побольше условий» и «без повторов».
* **В саму сборку (`FingerprintManager.create`) и в UI отбор пока не включён** —
  это следующий шаг, отдельным решением.
