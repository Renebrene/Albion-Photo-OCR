# Виртуальная сортировка

Дата: 2026-10-17

## Кнопка

«Запустить виртуальную сортировку» (техраздел → «Сортировка») ставит DINO batch
только для фото, у которых ещё нет успешного DINO; уже рассортированные
пропускаются. Задание создаётся с `auto_hybrid=true`: после успешного DINO
воркер сам ставит HYBRID_RUN с тем же `run_history_id`, поэтому один клик
выполняет DINO + HYBRID.

Кнопка заблокирована, пока идёт любой процесс, меняющий состояние
распознавания: `GET /v1/runs/activity` возвращает `pipeline` (ручной запуск или
расписание), `scheduler` или `sort`.

## Статистика

`GET /v1/sort/status` (scope `jobs:read`):

- `last` — самое свежее событие сортировки: ручной запуск (`kind=sort`),
  планировщик или стадия DINO/HYBRID внутри «Обновления базы». Содержит
  `stats.matched` (совпадения: HYBRID-вердикт этого же batch, иначе DINO best) /
  `stats.total` / `stats.failed`, статус и `has_log`;
- В общей истории запуска `counts.total` для DINO→HYBRID — уникальные фото;
  прогресс этапов хранится отдельно в `counts.by_stage.DINO/HYBRID`. Фото не
  суммируются дважды; jobs counters (`jobs_total/jobs_done`) считают queue jobs.
- `current` — активный DINO batch (для «Совпадений: X из Y» в процессе);
- `modes` — последние запуски по режимам:
  - `manual` — кнопка «Запустить виртуальную сортировку» (`kind=sort`);
  - `schedule` — тик планировщика (`kind=scheduler`);
  - `outofqueue` — сортировка из других мест (`mode=outofqueue`);
  - `pipeline` — стадия DINO/HYBRID последнего «Обновления базы»
    (`pipeline_run_stages.ref.batch_id`). Отдельной записи `kind=sort` у
    пайплайна нет, поэтому без этого fallback верхний блок показывал `0 из 0`;
- `active` — текущая операция пайплайна (если есть).

Первый блок вкладки показывает «Совпадений: X из Y», источник (вручную, по
расписанию, вне очереди, обновление базы), бейдж **ОК / ПРОЦЕСС / ОШИБКА**,
ссылку «Лог ошибок» и четыре даты по режимам. Таблицы DINO/HYBRID и заданий
остались ниже.

`matched` считается только по HYBRID-результатам того же DINO batch: старый
вердикт другого batch не должен делать новый batch «уже совпавшим».

## Скрытые слепки

Слепок с `active = false` (переключатель «Активен» в окне «Слепки») остаётся на
диске и в реестре, но не участвует в распознавании:

- `DinoRunner._load_fingerprints()` пропускает его при загрузке — он не входит
  в ranking;
- `hybrid.database.get_run_items()` вырезает его кандидатов даже из старого
  DINO batch и сбрасывает `dino_best_id`, если тот указывает на скрытый слепок;
- панель «Адреса» его не показывает (см. `frontend_quasar.md`).

Если реестр недоступен или пуст, фильтр отключается: поведение остаётся
прежним (все слепки с диска), чтобы старая БД без schema/023 не перестала
распознавать.

## Пересчёт после изменения набора слепков

Замена, добавление, архивирование или переименование слепка **не запускают**
DINO/HYBRID автоматически. Добавление или изменение слепков меняет эталонные
векторы, поэтому сохранённые вердикты могут устареть, но пересчёт запускает
оператор вручную из вкладки «Сортировка», когда будет готов.

- `POST /v1/fingerprints/build` и `build-batch` только ставят задание сборки
  (`FINGERPRINT_BUILD`) с `recalculate=false`; после публикации векторов
  пересчёт не ставится.
- `PUT /v1/fingerprints/registry/{id}` (переименование, описание, архив,
  повторное включение) не ставит пересчёт и не возвращает поле `recalc`.
- Набор фото и версии слепков фиксируются «Сортировкой»; явный ручной запуск
  делает результат воспроизводимым и не запускает долгий проход неожиданно.

Механизм `app.dino.recalc.enqueue_recalculation()` остаётся в коде для явного
вызова из сортировки/эксперимента; он дедуплицирует проход advisory lock'ом.
Прогресс и результат ручного прохода видны как обычная сортировка
(`kind=sort`, `mode=outofqueue`) в верхней карточке вкладки «Сортировка».
